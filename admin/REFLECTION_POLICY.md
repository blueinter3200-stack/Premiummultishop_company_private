# Reflection Policy

관리자 전용 운영 기준입니다. 평소 대표님 LLM의 기본 읽기 대상이 아닙니다.

## 아이디어/문제 반영
- 저장 기록을 공식 기준으로 자동 승격하지 않는다.
- 관리자가 명시적으로 `/아이디어반영` 또는 `/문제반영`할 때만 관련 공식 소스를 수정한다.
- 관련 없는 문서는 수정하지 않는다.
- 반영 후 해당 기록 상태를 갱신한다.
- 반영 성공 후 해당 항목을 `records/PENDING_INDEX.md`에서 제거한다.
- 반영이 실패하면 pending index만 먼저 제거하지 않는다.
- 반영 결과가 현재 진행업무에 영향을 주면 `working/CURRENT_WORK.md`도 최신 공식 기준과 모순되지 않도록 재정리한다.

## 반영미리보기
- 대표님과 관리자는 `/반영미리보기`를 사용할 수 있다.
- `/반영미리보기`는 read-only이며 실제 반영을 수행하지 않는다.
- 대상 저장 기록과 현재 공식 기준을 비교해 예상 변경, 영향 범위, 충돌, 확인 필요사항, 예상 변경 파일을 보여준다.
- 미리보기 결과가 긍정적이어도 `/아이디어반영`, `/문제반영`, `/업무확정`을 자동 실행하지 않는다.
- 세부 규칙은 `llm-source/REFLECTION_PREVIEW.md`를 따른다.

## 대표업무점검
- `/대표업무점검`은 관리자 전용 read-only 감사 기능이다.
- 대표님이 GitHub에 남긴 `records/ideas/representative/`, `records/problems/representative/`, `records/PENDING_INDEX.md`, `working/CURRENT_WORK.md`, `working/HISTORY.md`를 기준으로 기록 관리 상태를 점검한다.
- 대표님의 미반영 기록, PENDING_INDEX 누락/불일치, 업무공유 흔적, CURRENT_WORK 연결 여부, 일정/후속 액션을 회의 전에 확인한다.
- 저장되지 않은 대화나 회사 밖에서 한 행동은 추정하지 않는다.
- 점검 결과로 기록·index·공식 기준을 자동 수정하지 않는다.
- 세부 규칙은 `admin/REPRESENTATIVE_REVIEW.md`를 따른다.

## 업무검토와 업무공유
- 업무 대화는 자유롭게 진행한다.
- `/업무검토`는 최신 `main`의 공식 소스, CURRENT_WORK, PROJECT_REPOSITORIES, PENDING_INDEX를 확인하는 읽기 전용 게이트다.
- PENDING_INDEX에서 현재 업무와 관련된 미반영 아이디어·문제만 선별해 읽는다. 전체 기록을 매번 훑지 않는다.
- 검토 결과가 `PASS / 공유 가능`인 경우에만 같은 대화에서 `/업무공유`한다.
- 검토 후 핵심 내용이 바뀌면 다시 검토한다.
- PASS는 공식 확정이 아니다. CURRENT_WORK에 공유할 수 있다는 뜻이다.

## 업무확정
- 관리자만 실행한다.
- `working/CURRENT_WORK.md`에 이미 공유된 협의/진행 항목 중 관리자가 명시적으로 확정한 내용만 `llm-source/`로 승격한다.
- 기존 확정 요구사항을 바꾸는 경우 이전 기준을 교체하고 `docs/requirement-changelog.md`에 남긴다.
- 확정된 항목은 CURRENT_WORK에서 `최근 확정`, `완료`, 또는 남은 협의사항 형태로 재정리한다.
- 변경안이 공식 확정 전이라면 기존 공식 기준을 유지하고 CURRENT_WORK에 변경 협의 중임을 별도 표시한다.
- 업무확정에서 참고한 미반영 아이디어·문제는 자동으로 반영 처리하지 않는다. 해당 기록 자체의 공식 반영은 `/아이디어반영` 또는 `/문제반영`으로 별도 수행한다.

## 프로젝트 저장소
- 프로젝트 저장소명은 `llm-source/PROJECT_REPOSITORIES.md`에서 확인한다.
- 실제 구현 상태나 최근 변경이 필요한 판단에서는 해당 저장소 최신 `main`을 직접 확인한다.
- 새 회사 프로젝트 저장소를 공식 레지스트리에 추가하거나 제거하는 것은 관리자 관리 범위다.

## 역할 경계
- 대표님: 아이디어/문제 저장, 업무검토, 업무공유, 반영미리보기 가능
- 관리자: 위 기능 + 대표업무점검, 아이디어반영, 문제반영, 업무확정 가능

대표님은 데이터·제안·진행상황을 저장하고 공유할 수 있지만 공식 기준을 직접 변경하지 않는다.
관리자는 저장 기록과 진행업무를 검토해 실제 반영·확정 여부를 결정한다.

세부 업무검토 규칙은 `llm-source/WORK_GOVERNANCE.md`를 따른다.
