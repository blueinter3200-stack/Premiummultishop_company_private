# Administrator Reflection Policy

- Updated: 2026-09-06
- Release: GOV-20260906-02
- 관리자: ACT-001 / Jin
- 정본 절차: `llm-source/ACTOR_REGISTRY.json`, `LLM_RUNTIME.md`, `WORK_GOVERNANCE.md`, `APPROVAL_GOVERNANCE.md`

공식 회사 기준·역할·승인 규칙의 변경은 관리자만 수행한다. 관리자의 현재 명시적 자연어 검토·반영 요청도 실행 지시로 인정하되, 일반 대화를 자동 확정으로 바꾸지 않는다. 검토→변경안 기록→범위가 명확한 승인→실제 저장→재조회 순서는 유지한다.

## actor와 기록

- 새 사람 추가, actor_id 발급, 역할·프로젝트 연결 변경은 관리자 범위다.
- actor_id는 재사용하지 않는다.
- 역할이 바뀌어도 과거 기록의 actor_id를 변경하지 않는다.
- 다른 사람이 자리를 인수하면 새 actor_id를 발급한다.
- 기존 role 기반 아이디어/문제 경로는 참조 안정성을 위해 이동하지 않는다.

## 아이디어/문제 반영

아이디어/문제는 관리자가 특정 내용의 공식 채택을 지시한 경우만 반영한다. 대상 record_id·author_id·원문·정제본·공식 기준·현재 업무를 대조하고 필요한 변경만 적용한다. 공식 반영과 원기록 상태·pending index를 함께 갱신한다. 실제 해결 증거 없이 문제를 resolved로 표시하지 않는다. 단순 참고·전처리·인덱스 정리는 반영이 아니다.

## 업무검토 라우팅

`/업무검토` PASS는 자동 `/업무공유`가 아니다.

- idea → `/아이디어저장`
- problem → `/문제저장`
- work → `/업무공유` 또는 `/업무접수`
- mixed → 아이디어/문제와 work를 별도 ID로 연결
- policy_change → 관리자 확정 전 변경안으로 유지

대표님의 탐색·아이디어를 CURRENT_WORK로 잘못 승격하지 않는다.

## 업무확정과 결재

업무확정은 회사 정책·요구사항 개정이다. 영상·기획 결과 수락과 게시·지출 승인은 범위를 나눈 결재 기록으로 처리한다. 완료 업무를 전부 COMPANY_OS에 누적하지 않는다.

현재 상태의 원장은 work/items다. 변경 시 CURRENT_WORK와 assistant/30-working을 원장 기준으로 갱신한다. 기존 상태·원본·이력을 보존한다. 역할별 기록·개인정보·실제 도구 권한 경계를 지킨다.

대표업무점검은 읽기 전용이며 저장 기록·현재 업무·미반영 연결·날짜·후속 질문만 정리한다. GitHub에 없는 대화나 실제 행동을 추정해 `안 했다`고 단정하지 않는다.
