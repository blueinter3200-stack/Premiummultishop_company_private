## 외부 데이터 확인 계획

### 1. 오케이몰·크림·필웨이 랭킹
각 사이트에서 실제 확인 가능한 랭킹의 범위, 카테고리, 상품 식별자, 브랜드, 상품명, 현재 순위, 이미지 URL/이미지 표시 가능 여부, 갱신 주기, 과거 스냅샷 저장 가능 여부를 확인한다.

최소 데이터 필드 후보:
- source_site
- source_product_id 또는 source_url
- brand
- product_name
- model_code/style_code(확인 가능한 경우)
- source_category
- normalized_category
- rank_current
- rank_1d_ago
- rank_3d_ago
- rank_7d_ago
- rank_change_1d / 3d / 7d
- trend_code
- image_url
- snapshot_at
- source_checked_at

과거 1일·3일·7일 순위를 보려면 최소 일 1회 동일 기준시각의 스냅샷을 저장하는 구조를 우선 검토한다. 사이트 갱신 주기나 접근 제한이 다르면 실제 확인 결과를 기준으로 수집 주기를 조정한다.

### 2. 순위 변동 상태 코드
코드는 숫자 변동을 한눈에 보기 위한 파생값으로 정의한다.

기본 후보:
- NEW: 이전 비교시점에 없고 현재 랭킹에 새로 진입
- UP: 비교시점보다 순위 상승
- RAPID_UP: 일정 폭 이상 급상승
- SAME: 동일 또는 실질 변동 없음
- DOWN: 순위 하락
- OUT: 이전에는 있었으나 현재 랭킹 범위에서 이탈

RAPID_UP의 정확한 임계값과 SAME 허용폭은 실제 랭킹 분포·수집 범위를 확인한 후 수치 기준을 제안하고 관리자/개발자 확인 없이 확정값으로 만들지 않는다.

순위 변화량은 “이전 순위 - 현재 순위”처럼 방향이 명확한 계산식을 사용하고, 순위가 없는 경우 null/NEW/OUT을 숫자 0으로 대체하지 않는다.

### 3. 상품 이미지
시트에서 썸네일을 바로 볼 수 있도록 하되, 데이터 원본에는 image_url과 source_url을 별도 필드로 보존한다. 이미지가 임베드되어도 출처 URL/상품 식별자가 사라지지 않게 한다.

이미지 저장·캐싱·직접 수집 방식은 각 사이트의 실제 접근 방식과 허용 범위를 확인한 뒤 개발 요구사항에 명시한다. 접근 불가 이미지는 임의 대체하지 않는다.

## 통합 데이터 구조와 시트 설계

중복 데이터를 여러 시트에 복사하기보다 “정규화된 마스터 데이터 + 목적별 보기(View)” 구조를 우선안으로 제안한다.

### 마스터/원천
- 00_DATA_DICTIONARY: 필드명, 정의, 형식, null 처리, 출처
- 01_RANK_MASTER: 세 사이트 랭킹 원천과 스냅샷 통합
- 02_PRODUCT_MASTER: canonical_product_id 기준 상품 마스터
- 03_SOURCE_MAPPING: canonical_product_id ↔ 사이트별 상품 ID/URL 연결

### 조회/분석
- 10_ALL_RANK: 세 사이트 랭킹 통합 조회
- 11_CATEGORY_VIEW: 상의·아우터·바지·가방/잡화 등 카테고리별 필터/보기
- 12_COMMON_PRODUCTS: 2개 이상 사이트에서 공통으로 잡힌 상품과 사이트별 순위 비교
- 13_DEMOGRAPHIC: 성별·연령대 선호 근거가 있는 상품만 표시
- 14_SOCIAL_TREND: 유튜브·인스타그램 브랜드/상품 트렌드 변화
- 15_OUR_CATALOG_MATCH: 프리미엄멀티샵 등록 상품과 외부 랭킹 상품의 일치/유사/미보유 상태
- 16_BUYING_PRIORITY: 추가 사입 후보 및 근거
- 99_OPEN_ISSUES: 미확인·접근불가·매칭애매·개발자 확인 질문

최종 탭명은 기존 시트 구조가 있다면 충돌하지 않도록 조정한다.

## 상품 통합·공통상품 매칭 방법

세 사이트의 동일 상품을 하나로 묶기 위해 canonical_product_id 개념을 사용한다.

매칭 우선순위 후보:
1. 동일한 공식 모델코드/style code가 있으면 최우선
2. 브랜드 + 모델명/상품명 정규화 + 핵심 옵션을 조합
3. 이름만 비슷한 경우 자동 확정하지 않고 fuzzy_match_candidate로 분리
4. 색상·사이즈 차이는 같은 모델의 variant인지 별도 SKU인지 원본 구조에 따라 구분
5. 애매한 매칭은 수동 확인 대상으로 남김

자동 병합 때문에 서로 다른 상품이 하나로 합쳐지는 오류를 막기 위해 exact_match / probable_match / unmatched 상태를 둔다.

## 카테고리 표준화 방법

사이트별 카테고리명을 그대로 보존한 source_category와 회사 공통 normalized_category를 분리한다.

초기 공통 카테고리 후보:
- 상의
- 아우터
- 바지
- 원피스/스커트(해당 시)
- 신발
- 가방
- 액세서리/잡화
- 기타/미분류

실제 기존 회사 카테고리 체계가 Drive에 있으면 그 체계를 우선하고, 없는 경우에만 위 후보를 관리자 확인용으로 제안한다.

## 성별·연령대 선호 분석 방법

랭킹 순위만으로 성별·연령대 선호를 추정하지 않는다.

우선순위:
1. 외부 사이트가 직접 제공하는 성별·연령대 통계가 있으면 출처와 기준기간을 함께 저장
2. 회사 내부 고객/판매 데이터에서 합법적이고 허용된 범위의 집계 데이터가 있으면 상품/SKU별 성별·연령대 분포를 연결
3. 광고/분석 플랫폼 등 별도 출처가 있으면 출처별로 분리
4. 근거가 없으면 unknown으로 두고 AI 추정값을 사실 데이터처럼 넣지 않음

필드 후보:
- demographic_source
- gender_segment
- age_band
- preference_metric
- sample_period
- sample_size(확인 가능한 경우)
- verified_at

개인식별정보는 수집하지 않고 집계 수준만 요구한다.

## 유튜브·인스타그램 트렌드 분석 방법

목적은 “SNS 반응 증가 = 바로 사입”으로 단정하는 것이 아니라, 랭킹·자사 재고/판매·브랜드 공백과 함께 판단할 보조 신호를 만드는 것이다.

실행 승인 후 확인할 신호 후보:
- 브랜드/상품 언급 게시물 수
- 조회/좋아요/댓글 등 공개 반응
- 일정 기간의 증감률
- 반복 노출되는 상품/모델
- 신규 급증 키워드/브랜드
- 게시일·관측일·플랫폼

가능하면 7일/30일 등 비교기간을 두되, 정확한 기간과 API/수집 가능 필드는 실제 접근 방식 확인 후 확정한다.

조회수·좋아요 증가만으로 매출 또는 구매 의도를 확정하지 않는다. 소셜 트렌드는 보조 신호로만 사용한다.

## 프리미엄멀티샵 상품 매칭과 사입 우선순위

자사 상품 마스터와 외부 랭킹 canonical_product_id를 연결해 다음 상태를 만들 계획이다.

- OWNED_LISTED: 현재 등록/보유 확인
- OWNED_LOW_COVERAGE: 보유하나 브랜드/카테고리 커버리지 부족 후보
- NOT_OWNED: 외부 랭킹에는 있으나 자사 미보유
- MATCH_UNCERTAIN: 상품 매칭 미확정

사입 우선순위는 단일 신호가 아니라 아래 요소를 분리하여 보여준다.
- 세 사이트 중 몇 곳에 동시에 등장하는지
- 현재 순위와 1/3/7일 순위 변화
- 소셜 트렌드 변화
- 자사 보유 여부/재고 커버리지
- 브랜드·카테고리 공백
- 내부 판매/회전 데이터가 확인되는 경우 해당 성과

최종 priority_score의 가중치는 실제 데이터 분포를 확인한 뒤 별도 제안한다. 현재 단계에서 임의 가중치로 “사입 1순위”를 확정하지 않는다.

## 적용 기준과 주요 판단 이유

1. 원천 데이터와 파생 분석을 분리한다.
   - 사이트 원천 랭킹/이미지/상품정보를 먼저 보존하고, trend_code·공통상품·우선순위는 파생 필드로 계산한다.

2. 단일 마스터 + View 구조를 우선한다.
   - 세 사이트/카테고리/공통상품별로 데이터를 따로 복제하면 불일치가 생기기 쉬우므로 한 마스터에서 필터/뷰를 제공하는 방향이 유지보수에 유리하다.

3. 상품 식별자를 중심으로 연결한다.
   - 상품명 문자열만으로 합치지 않고 사이트별 ID와 canonical_product_id를 함께 둬 잘못된 통합을 줄인다.

4. 이미지 URL을 데이터로 보존한다.
   - 시트 썸네일 표시와 별개로 원본 이미지 출처와 상품 식별을 추적할 수 있어야 한다.

5. 인구통계·소셜 반응은 근거 출처를 분리한다.
   - 확인되지 않은 성별/연령대와 SNS 반응을 랭킹 데이터에서 임의 추론하지 않는다.

6. 사입 우선순위는 설명 가능한 근거로 만든다.
   - 단일 점수만 보여주지 않고 어떤 신호 때문에 우선순위가 올라갔는지 추적 가능하게 한다.
