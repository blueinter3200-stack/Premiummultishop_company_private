# PMS Revenue Commerce OS v2.0 — 수익 학습형 사업 설계

- 기준일: 2026-08-15
- 사업: Premium MultiShop
- 상태: 통합 설계 확정 / 실제 수익 개선은 데이터 연결·소량 테스트 후 검증

## 1. 최종 목적

PMS의 목표는 AI 기술 회사가 되는 것이 아니다.

> **세계 공급망에서 지금 살 가치가 있는 상품을 찾아, 실제 기여이익·현금회수·재구매까지 회수하는 수익 운영체계**가 되는 것이다.

매출이 증가해도 다음이 악화되면 성공으로 판정하지 않는다.

- 주문당 기여이익
- 순마진율
- 현금회수기간
- 재고회전일
- 반품·보상·A/S 비용
- 고객획득비용
- 재구매율
- 장기재고·최대손실

현재 실제 원가·현금·반품·재고·고객 식별 데이터가 완전히 연결되지 않았으므로, 대량 발주·광고 확대·전사 할인은 검증 전 보류한다.

## 2. PMS 5대 수익 엔진

### Engine 1 — Demand Engine

고객이 실제로 살 가능성을 판단한다.

- 검색·조회는 초기 신호
- 상담·장바구니는 중간 신호
- 결제·수령은 확정 신호
- 재구매·추천은 장기 신호

검색량만으로 발주하지 않는다.

### Engine 2 — Sourcing Engine

공급·정품·권리·재고·납기·반품을 검증한다.

- 국내 READY: 신뢰·속도·실물 확인
- 해외 RARE: 가격·희소성·구색
- CARE: A/S·수선·세탁·보관·재판매 지원

### Engine 3 — Profit & Cash Engine

상품·주문·채널·고객별 실현 수익을 계산한다.

### Engine 4 — Trust & Service Engine

상품여권·검수·배송·통관·반품·보상·A/S를 주문 ID와 연결한다.

### Engine 5 — Learning Engine

예측과 실제의 차이를 기록하고, 오류 원인과 규칙 후보를 만든다. 규칙은 대표 승인 전까지 자동 적용하지 않는다.

## 3. Revenue Decision Engine v2

### CM0 — 상품 자체 기여이익

```text
CM0
= 순판매금액
- 상품 매입원가
- 환율·환전비용
- 국제운송·국내운송
- 관세·통관·부가세
- 국내 입고·검수비
```

### CM1 — 주문 실현 기여이익

```text
CM1
= CM0
- 결제·플랫폼 수수료
- 포장·출고 비용
- 고객응대 비용
- 할인·쿠폰·사은품
- 예상 반품·취소·불량 충당금
```

CM1이 음수인 주문은 매출 규모와 관계없이 확대하지 않는다.

### CM2 — 채널·캠페인 기여이익

```text
CM2
= CM1
- 주문 귀속 광고비
- 제휴·인플루언서 수수료
- 콘텐츠 배부비
- CRM 발송비
```

### CM3 — 고객·서비스 포함 기여이익

```text
CM3
= CM2
- CAC
- 실제 A/S·수선·세탁 비용
- 고객별 반품·클레임 비용
- VIP 혜택·상담·배송 업그레이드 비용
+ 검증된 실제 재구매 기여이익
```

미래 재구매를 최초 주문의 이익으로 선반영하지 않는다. 최초 주문은 CM1·CM2로 승인하고, 고객 투자·CRM 확대는 실제 재구매 기반 LTV로 판단한다.

### BEP와 현금

```text
BEP 주문수 = 테스트 고정비 / 주문당 CM1

회수기간 = 투입 현금 / 월 실제 회수현금

재고위험액 = 매입현금 + 미회수 비용 + 예상 처분손실
```

## 4. 승인 규칙

| 결정 | 승인 기준 |
|---|---|
| 후보 조사 | 데이터 출처·기준일·신뢰도 존재 |
| 상품 테스트 | CM1 양수 가능성·최대손실·증빙 확보 |
| 발주 | 대표 승인·공급·정품·통관·반품 조건 확인 |
| 광고 확대 | CM2 양수·증분 기여이익 확인 |
| CRM 확대 | 동의·빈도제어·클레임 제외·증분 기여이익 확인 |
| 가격 변경 | 최소마진·최대할인·재고위험 통과 |
| 재고 처분 | CM1 회복 가능성·현금회수 효과·브랜드 훼손 검토 |
| 매장 축소·통합 | 90/180일 데이터와 고정비 절감 효과 확인 |

## 5. 학습 아키텍처

### 공통 실행 Envelope

모든 Agent 실행에는 다음을 저장한다.

- `run_id`
- `agent_id`
- `source_refs`
- `data_freshness`
- `data_quality_score`
- `model_version`
- `prompt_version`
- `rule_version`
- `confidence_score`
- `approval_id`
- `forecast_id`
- `outcome_id`

### Agent Memory 계층

- `FACT`: 원본 데이터
- `EVIDENCE`: 인보이스·검수·가격·배송 증거
- `DECISION`: 대표·Agent 판단
- `FORECAST`: 예측값
- `OUTCOME`: 실제 결과
- `ERROR`: 차이 원인
- `RULE_CANDIDATE`: 새 규칙 후보
- `RULE_APPROVED`: 승인된 규칙
- `POLICY`: 하드스톱·권한·금지정책

### 모델·규칙 승격

```text
DRAFT → SHADOW → CANARY → APPROVED → RETIRED
```

- DRAFT: 문서·프롬프트 초안
- SHADOW: 실제 결정에 영향 없이 병렬 평가
- CANARY: 제한된 5 SKU·소수 고객에 시험
- APPROVED: 대표 승인 후 운영 적용
- RETIRED: 성능 저하·오류 반복·정책 변경 시 폐기

### 예측-실제 평가 시점

- D+7: 초기 반응
- D+14: 판매 가능성
- D+30: 손익·재고회전
- D+90: 재구매·장기 수익

오류 원인 코드:

- 수요 과대평가
- 가격 오류
- 원가 누락
- 경쟁력 부족
- 타깃 오류
- 콘텐츠 오류
- 채널 오류
- 공급 차질
- 데이터 오류
- 실행 지연
- 외부 시장 변화

같은 오류가 2회 반복되면 Agent 프롬프트가 아니라 데이터·판정규칙·하드스톱을 재검토한다.

## 6. 자동화 등급

### 자동 실행 가능

- 로그 생성
- 내부 ID 중복 탐지
- 재고 수량 차이 경고
- 고객 등급 계산
- 배송 상태 동기화
- D+7/D+14 리포트 생성
- 후보 세그먼트 생성

### 예외 검토 후 실행

- 추천 상품 분류
- 가격 변경 후보
- 배송 지연 안내 초안
- CRM 대상 후보
- 재고 이동 후보
- 품절·stale 재고 HOLD

### 대표 승인 필수

- 신규 상품 공개
- 가격·할인 변경
- 발주·결제
- 고액 환불·보상
- 대규모 CRM
- 공급처 변경
- 정품·통관·법적 판단
- 매장 축소·통합·폐점

### 금지

- AI 단독 발주
- AI 단독 환불·보상 확정
- AI 단독 고객 병합
- 정품·통관·수입자 판단 자동 확정
- 미동의 고객 대량 발송
- 원가·수수료가 빠진 마진 계산

## 7. 90일 실행 로드맵

### 0~30일 — 기준선과 신뢰상품 검증

- 5 SKU: READY 3개·RARE 2개
- 상품여권 적용
- SKU·주문·고객·채널 내부 ID 발급
- CM1·CM2 수동 원장
- 상담→결제→배송→반품 연결
- D+7·D+14 예측 저장

중단:

- 원가·재고·고객 ID 불일치
- 정품·통관 증빙 공백
- CM1 계산 불가
- 동의 데이터 없음

### 31~60일 — 고객·채널·재고 최적화

- VIP·브랜드 충성·휴면위험·신규 신뢰형·할인민감 세그먼트
- 카카오 상담·CRM 제한 테스트
- READY/RARE 콘텐츠 분리
- 광고는 CM2 확인 캠페인만 확대
- 예약 쇼룸은 고가·사이즈 상담 상품 중심

중단:

- 증분 기여이익 음수
- 반복 민원·반품 증가
- 고객 동의·빈도제어 미흡
- 해외 주문형 조달·통관 실패

### 61~90일 — 매장·공급·채널 게이트

- 채널별 CM2 비교
- 매장별 고정비·매출·상담·온라인 전환 비교
- READY/RARE 재고 비중 재설계
- 재고 처분·이동·3PL 후보 판정
- 유지·축소·예약제·창고 통합 시나리오 비교

폐점은 온라인 매출 증가만으로 결정하지 않는다. 고정비 절감, 고객 이전, 재고 회수, 상담·A/S 품질을 함께 본다.

## 8. 180일 확장 로드맵

### 91~120일

- 성과가 검증된 카테고리만 확대
- 상품·고객·채널별 LTV 추적
- 공급처별 클레임·납기·정품증빙 점수화
- 읽기 전용 데이터 연동 검토

### 121~180일

- 검증된 SKU만 제한적 가격·재고 자동화
- VIP 예약 쇼룸을 고가 상담 거점으로 전환
- 표준 반복상품만 선택적 3PL
- 장기재고 처분 규칙 고도화
- 매장 포트폴리오 최종 결정

## 9. PMS의 방어 가능한 자산

1. SKU별 증거가 쌓이는 상품여권
2. 주문·재고·현금·반품·보상 이벤트 원장
3. 고객별 실제 구매·서비스·재구매 데이터
4. 공급처별 실패·클레임·정품·납기 기록
5. 예측과 실제 차이로 개선되는 소싱·가격 규칙
6. 고객이 문제 발생 시 판매자만 상대하는 책임 구조

최저가나 Agent 숫자는 복제할 수 있다. 그러나 이 운영 기록과 판단 데이터는 시간이 지날수록 PMS에 귀속되는 복합 자산이 된다.

## 10. 최종 게이트

PMS의 다음 단계는 데이터가 없는 상태에서 AI를 더 붙이는 것이 아니다.

```text
실제 데이터 연결
→ 수익 원장 정합성
→ 5 SKU 테스트
→ 예측/실제 기록
→ 손실 원인 분석
→ 규칙 후보 생성
→ 대표 승인
→ 제한 적용
→ 실제 성과 재검증
```

이 순서를 통과하지 못하면 개발·광고·발주를 확대하지 않고 `검증 보류`로 둔다.
