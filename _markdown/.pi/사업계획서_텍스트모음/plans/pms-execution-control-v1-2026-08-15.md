# PMS 실행 운영·통제 고도화 구조 v1.0

- 기준일: 2026-08-15
- 적용 범위: 네이버 AI 콘텐츠·SEO → 상품 판정·공개 → 광고·판매 → 카카오 CRM → 재구매·A/S
- 상태 표기: **확인된 사실 / 계산값 / 운영 제안 / 대표 결정 필요 / 검증 불가**
- 원칙: AI는 분석·초안·이상탐지까지만 수행한다. 가격·재고·상품 공개·광고 증액·CRM 발송·환불·고객 병합·발주는 Human-in-the-loop로 승인한다.

## 1. 운영 통제 구조

| 계층 | 시스템/운영 역할 | 자동화 허용 | 사람 승인 필수 | 하드스탑·통제 |
|---|---|---|---|---|
| Master | Product/Customer/Order/Inventory/Consent Master | 읽기·동기화·중복탐지 | 마스터 수정·병합·삭제 | 원천·기준일·수정자 없는 값은 `검증 불가` |
| Rule Engine | 마진, 정품·통관, 재고, 동의, 가격, 반품 규칙 | 판정·보류·알림·자동 차단 | 예외 승인 | 순마진율 12% 미만, 회수 6개월 초과, 재고회전 90일 초과 등 기존 하드스탑 유지 |
| AI Layer | 트렌드·키워드·상품 후보·콘텐츠 초안·세그먼트 제안 | 초안·요약·추천 | 최종 사실·표현·대상·실행 승인 | AI 산출물 단독 발주·공개·발송 금지 |
| Execution | Cafe24/스마트스토어·Google Ads·네이버·카카오·물류 | 승인된 작업의 예약 실행 | 신규 공개·예산·가격·대량 발송 | 승인 토큰 없는 쓰기 API 거부, `SHIPMENT_HOLD` 지원 |
| Evidence | 승인·변경·예외·검수·성과 로그 | 이벤트 자동 기록 | 사후 검토·예외 종료 | 모든 실행에 actor, approver, before/after, 근거 링크 필수 |

## 6. 재고·반품·A/S 운영 통제

| 이벤트 | 상태 흐름 | 필수 처리 | 통제/중단 |
|---|---|---|---|
| 입고 | `RECEIVING → AUTH_CHECK → QC_PASS/FAIL → AVAILABLE/HOLD` | 수량·시리얼·사진·인보이스·정품 증빙·하자 기록 | 검수 미완료 상품 공개·출고 금지 |
| 판매 예약 | `AVAILABLE → RESERVED → PAID → ALLOCATED` | 주문·결제·재고 원장 일치 | 재고 부족·가격 변경·결제 미확인은 출고 HOLD |
| 출고 | `ALLOCATED → PACKED → SHIPPED → DELIVERED` | 포장자/검수자, 운송장, 출고시각, 상품상태 | 배송지연 SLA 초과 CS 에스컬레이션 |
| 반품 접수 | `REQUESTED → ELIGIBILITY_CHECK → APPROVED/REJECTED` | 사유코드, 기간, 사용/훼손, 배송비 책임, 증빙 | 고의 훼손·정품 분쟁은 일반 자동환불 금지 |
| 반품 입고 | `RETURN_IN_TRANSIT → RECEIVED → QC → REFUND/EXCHANGE/DISPUTE` | 반품 사진·검수자·환불액·재고 재분류 | 검수 전 환불 금지(법정 의무·대표 예외 제외) |
| A/S | `OPEN → QUOTE → CUSTOMER_APPROVAL → IN_SERVICE → QC → CLOSED` | 증상·책임주체·예상비용·납기·고객 승인·완료 증빙 | 비용/책임 불명확 시 대표 또는 전문가 검토 |
| 장기재고 | `SLOW → RISK → RECOVERY_PLAN → SOLD/WRITE_OFF` | 7/30/90일 판매량, 회수금액, 할인·묶음·이동 계획 | 추가 발주 중지, 할인 후 기여이익 재계산 |

## 7. 30/60/90일 KPI 및 게이트

목표 수치는 **운영 제안**이며 기준선 수집 후 대표 확정. 기존 하드스탑은 목표가 아니라 즉시 차단 기준이다.

| 기간 | 목적 | 필수 KPI | 통과 제안 | 미달 조치 |
|---|---|---|---|---|
| D+30 | 측정·통제 복구 | 주문-결제-재고 일치율, Purchase 오차, 승인 로그 완결률, 콘텐츠/광고/CRM 추적률, 반품·출고 SLA | 핵심 이벤트 추적 100%, 주문-Purchase 오차 ±10% 이내, 승인 로그 100%, 재고 정확도 98% 이상(대표 확정 필요) | 자동화 확대 금지, 데이터 복구 스프린트 |
| D+60 | 제한 테스트의 경제성 검증 | 광고 포함 채널별 기여이익, SEO 상품 클릭→상담→주문, CRM 발송당 기여이익, SKU 판매속도, 반품률, 재고회전 | 캠페인/테스트별 기여이익 0 초과, 하드스탑 통과, CRM 수신거부·불만 이상 없음, 재고 회수계획 존재 | 예산·노출·발송 축소, SKU 추가 발주 중단 |
| D+90 | 반복 가능한 수익 루프 판정 | 월 순이익, 순마진율, 현금회수기간, 재고회전일, 재구매율, CRM 기여매출, 채널별 기여이익, 장기재고 금액 | 월 순이익 50만원 이상, 순마진 12% 이상, 회수 6개월 이내, 회전 90일 이내 및 재구매·현금 개선(세부 목표 대표 확정) | 유지/축소/통합/연기 중 대표 판정; 자동 확장 금지 |

## 8. 중단조건과 재개조건

|---|---|---|---|
| 정품·통관·상표·A/S 책임 증빙 불가 | 상품 공개·광고·발주 전면 HOLD | 증빙 원본·책임주체·검수 완료 | 대표 + 전문가 검토 |
| 순마진 12% 미만, 기여이익 0 이하, 회수 6개월 초과 | 신규 유입·추가 발주·증액 중지 | 원가/가격/채널 수정 후 재계산 통과 | 대표 |
| 재고회전 90일 초과 또는 14일 연속 판매 없음 | 발주 중단, 재고회수 플랜 | 회수 전략·할인 후 손익 승인 | 대표/MD |
| 주문·재고·가격 불일치, 품절·오가격 노출 | 판매·출고·광고 HOLD, 원복 | 원장 대조·샘플 주문·대표 페이지 검수 | 운영 + 대표(고객 영향 시) |
| 전환 태그 오차 ±10% 초과, 데이터 중복 | 광고 최적화·증액 중지 | 테스트 주문과 이벤트 정합성 확인 | 개발 + 광고 책임자 |
| CRM 동의 불명·수신거부 누락·중복/과다 발송 | 캠페인 즉시 중지, suppression 적용 | 동의·제외·빈도·사과/보정 프로토콜 확인 | 대표 + 개인정보 검토 |
| 반품·분쟁·A/S 비용으로 기여이익 악화 | 해당 SKU/캠페인 축소·보류 | 원인 개선·정책·공급책임 재확인 | 대표 |
| 플랫폼 정책·법적 이슈·보안사고 | 관련 자산/계정 쓰기 차단, 증거 보존 | 전문가 검토 및 시정 확인 | 대표 |

## 11. 구현 우선순위

| 단계 | 기간 | 구현물 | 완료 정의 |
|---|---:|---|---|
| P0 | 0~30일 | 승인 큐, 상태값(HOLD 포함), 감사로그, 주문-재고-광고 이벤트 대조, 콘텐츠 QA 템플릿 | 승인 없는 쓰기 실행 0건, 핵심 이벤트와 로그 100% 연결 |
| P1 | 31~60일 | 상품 공개 게이트, CRM 동의·suppression, 반품/RMA 상태, D+7/14 리포트 | SKU 5개 이하 테스트와 CRM 제한 발송이 증거 기반으로 반복 가능 |
| P2 | 61~90일 | 30/60/90 대시보드, 예외 만료·원복, 채널별 기여이익, 재고회수 워크플로 | 대표가 유지/축소/확대/중단을 로그와 손익으로 판정 가능 |

> 핵심 결론: PMS 고도화의 첫 목표는 자동화율이 아니라 **승인 없는 위험 실행을 0으로 만들고, 콘텐츠·광고·상품·CRM·재고를 하나의 기여이익과 감사로그로 연결하는 것**이다. 하드스탑을 통과하지 못한 데이터는 자동화 대상이 아니라 `검증 보류`다.
