# PMS 계단형 상품 구조 수익성 재설계 v2

- 기준일: 2026-08-16
- 대상: Premium MultiShop
- 목적: 매출 확장이 아니라 CM1/CM2/CM3, 현금회수, 재고회전, 고객 LTV를 함께 개선하는 계단형 운영체계
- 상태: **운영 가설 및 검증 설계**. 실제 가격·마진·전환율·LTV 숫자는 확정하지 않음.

## 1. 한 줄 결론

현재 L0→L1→L2→L3→L4의 방향은 유지하되, **레벨을 가격대가 아니라 현금 노출·서비스 원가·증거 수준·고객 경제성으로 정의**한다. L1은 저가 매출을 늘리는 단계가 아니라 첫 주문에서 손익과 신뢰를 회수하는 단계, L2는 재고 기반 CM2 엔진, L3는 예약·검수 중심의 제한적 고액 판매, L4는 선입금/예약금으로 현금 선행을 확보하는 Concierge·B2B로 재설계한다.

확장 기본값은 `검증 보류`다. 실제 주문·원가·반품·정산·고객 ID가 연결되기 전에는 승급 자동화, 광고 확대, 고가 선매입을 승인하지 않는다.

## 2. 손익과 현금의 공통 정의(확정 전 정책 가설)

명칭이 비슷한 지표를 섞지 않도록 주문·SKU·고객·채널 단위로 동일한 원장에 기록한다.

- **매출**: 취소·환불을 제외한 실제 인식 기준을 회계/운영에서 확정.
- **CM1(상품 기여이익)** = 순매출 − 매입원가 − 국제운송/관세/부가세 등 landed cost − 입고검수·포장·기본배송의 주문 변동비.
- **CM2(판매/획득 기여이익)** = CM1 − 플랫폼·결제 수수료 − 할인·쿠폰·적립금 − 반품·취소·분쟁 예상/실제 비용 − 주문 귀속 광고비 − CRM/상담 변동비.
- **CM3(운영 기여이익)** = CM2 − 해당 레벨의 추가 인건비·검수/콘텐츠 제작·쇼룸·A/S 운영비. 공통 고정비 배부 전후는 별도 표시한다.
- **고객 LTV(관측 LTV)** = 고객별 누적 CM2(또는 사업자가 선택한 CM3) − 고객별 귀속 CAC/CRM 비용. 매출 LTV와 기여이익 LTV를 별도 표기.
- **현금회수기간**: 발주·선지급부터 고객 결제액이 실제 정산되어 사용 가능해질 때까지. 예약금은 조건부/환불가능 여부에 따라 가용현금을 구분.
- **재고 노출액**: 아직 고객 결제로 회수되지 않은 landed cost + 이미 지출한 검수/운송비. 고가 레벨은 매출보다 이 값을 먼저 승인한다.

위 정의와 비용 귀속 방식은 **대표 결정 필요**. 확정 전 숫자는 계산값으로 보고하지 않는다.

## 3. 재설계 원칙

1. 가격 범위는 역할을 설명하는 참고값일 뿐 승급 기준이 아니다. 현재 문서의 L1 3만~15만원, L2 30만~150만원, L3 150만~500만원은 **가격 가설**로 유지한다.
2. L0는 조회수·팔로워가 아니라 식별 가능한 구매의도와 후속 CM2로 평가한다.
3. 신규고객 획득을 위해 첫 주문 CM2 적자를 허용할 경우, 허용 적자·최대예산·회수기간·중단일을 캠페인 시작 전에 대표가 승인한다.
4. 재고가 필요한 L2/L3와 선주문형 L4를 분리한다. 예약/위탁/공급확정 없는 L3 고가 선매입은 기본 금지다.
5. 승급은 누적 매출이 아니라 `최근 기간의 CM2 양수 + 서비스 리스크 + 현금행동`을 함께 본다.
6. 강등은 고객을 벌주는 제도가 아니라 비싼 서비스·할인·재고 우선권을 경제성이 맞는 수준으로 되돌리는 제도다.
7. 모든 레벨에는 책임자, 검토주기, 다음 단계 CTA, 중단 조건이 있어야 한다.

## 5. 고객 이동 규칙

### 승급은 단일 점수가 아니라 필수 게이트 AND 조건

- **L0→L1**: 동의된 고객 ID + 특정 관심/가격대 + 구매조건 확인 + L1 SKU의 실제 원가/반품/정품 증거 + 상담 또는 구매 CTA.
- **L1→L2**: 첫 주문 수령완료 + 환불/클레임 처리완료 + 고객 선호 데이터 + L2 추천이 가격·재고·CM2 기준을 통과.
- **L2→L3**: 고가 구매 의향이 구체적(모델/예산/납기) + 상담원 서비스 원가를 포함한 CM2/CM3 양성 가설 + 상품여권·검수·A/S 책임 확인.
- **L3→L4**: 실제 고가 구매 또는 반복 구매 + 개인소싱/예약 요청 + 예약금·환불·조달실패 조건 서면 합의.

### 강등 규칙

- 최근 관측기간 동안 구매·상담이 없으면 VIP 우선권/개인소싱 리소스를 회수하고 L2 또는 L1 일반 CRM으로 전환한다.
- 할인만 반복 요구하거나 정상가 판매가 어려우면 할인 등급이 아니라 `가격민감 세그먼트`로 분리하고, CM2 양수 상품만 제안한다.
- 반품·클레임·A/S가 반복되면 고가 선예약을 막고 표준 증거·결제 조건으로 강등한다.
- 동의 철회/식별키 오류 고객은 즉시 마케팅 대상에서 제외한다. 운영·법무 검토 전 재접촉 금지.
- 강등/승급은 고객별 이력과 사유를 남기며, 자동 조치 전 사람 검토를 둔다.

### 레벨 이동 KPI의 기본 식

- 이동률 = 다음 레벨로 최초 이동한 고객 수 / 해당 레벨의 유효 고객 수
- 이동 소요일 = 레벨 진입일→다음 레벨의 첫 유효 행동일(구매·예약·상담 등)
- 이동 기여이익 = 이동 전후 일정 관측창의 고객 CM2 − 추가 CRM/상담/할인비
- 이동 품질 = 다음 레벨 이동 후 환불·클레임·강등을 반영한 순 이동률
- 레벨별 코호트 LTV = 동일 진입월/진입채널 고객의 누적 CM2(및 CM3 보조) 추적

관측창, 유효 고객, 귀속 규칙, 환불 인식시점은 **필수 데이터가 생긴 뒤 확정**한다.

## 6. 레벨별 현금 통제

- **L0**: 콘텐츠 제작·도구·광고·CRM 비용을 캠페인별 선등록. 무료라는 이유로 비용을 0으로 처리하지 않는다.
- **L1**: 신규 매입보다 기존재고/소량 테스트 우선. `매입→판매→플랫폼 정산→반품종료` 현금 사슬을 SKU별로 기록한다.
- **L2**: 매입 승인 시 예상 판매기간이 아니라 실제 회전·정산 지연을 포함한 현금회수 시나리오를 사용한다. 할인 판매 시 CM2 재계산.
- **L3**: 노출액 상한, 고액 환불 대비 현금, 정품분쟁·A/S 비용 준비금을 주문별로 분리한다.
- **L4**: 예약금은 계약상 환불 의무가 있는 금액을 가용현금으로 간주하지 않는다. 고객 선입금으로 다른 주문/고정비를 메우지 않는다.
- 회사 공통 게이트: 다음 30일 현금 유입·유출, 미정산금, 환불예상액, 장기재고, 공급자 선지급을 주 단위로 확인한다. 데이터 미연결 시 확장하지 않는다.

## 7. 중단·재개 규칙

기존 PMS 하드스톱을 대체하지 않고 계단에 적용한다. 아래는 신규 발주/광고/서비스 확대의 **중단 트리거 가설**이며, 숫자는 기존 승인정책 또는 실제 데이터로 확정한다.

1. 주문 단위 CM2 또는 CM3가 음수이고 가격·원가·서비스 수정으로 회복 경로가 없으면 해당 제안 중단.
2. 판매속도·회전일·현금회수가 승인된 목표 미달이면 추가 매입을 중단하고 기존재고 회수 모드로 전환.
3. 콘텐츠가 조회수는 만들지만 식별 리드·상담·주문·후속 CM2가 연속 관측기간 동안 0 또는 비용 초과면 주제/CTA 중단.
4. Trend Scout 후보가 국내 가격·공급·정품·통관 증거를 확보하지 못하면 콘텐츠 아이디어로만 보류하고 발주 금지.
5. 반품·취소·분쟁·플랫폼 페널티가 원가에 반영되지 않았으면 손익을 `검증 불가`로 표시하고 확장 금지.
6. 현금 노출액이 가용현금 정책 한도를 넘거나 고우선 재고/환불 자금을 잠식하면 레벨과 무관하게 중단.
7. 재개는 원인 분류(수요 과대평가/가격/원가누락/채널/공급/데이터 등), 수정안, 소량 재테스트, 대표 승인 후에만 허용.

## 8. 무료 콘텐츠→CM2·LTV 검증식

### 8.1 식별·귀속 조건

콘텐츠마다 `content_id`, 발행일, 주제, CTA, 채널, 제작비, 광고/제휴비, CRM 비용, 연결 랜딩, 추천 SKU/레벨을 기록한다. 주문·상담·고객·정산에는 `customer_id`, `order_id`, `sku_id`, `campaign_id/content_id`, `channel_id`를 공유한다.

**직접 귀속 콘텐츠 CM2**

```text
직접 콘텐츠 CM2
= 콘텐츠 귀속 순주문 CM2
  − 콘텐츠 제작비
  − 콘텐츠 귀속 광고/제휴비
  − 콘텐츠 발송·CRM 변동비
```

**보조적인 보정 콘텐츠 CM2**

```text
보정 콘텐츠 CM2
= (콘텐츠 노출 고객 코호트의 관측 누적 CM2
   − 비교 코호트의 관측 누적 CM2)
  − 콘텐츠 추가비용
```

비교 코호트가 없거나 고객 ID·노출 로그가 불완전하면 보정 CM2는 `검증 불가`다. 마지막 클릭만으로 콘텐츠의 장기 LTV를 주장하지 않고, 직접 귀속과 보조 귀속을 분리한다.

**콘텐츠→LTV 연결 검증**

```text
증분 LTV
= 노출/유입 코호트의 고객별 관측 누적 CM2
  − 유사 비노출 코호트의 고객별 관측 누적 CM2
```

관측 누적기간, 코호트 매칭 기준, 신규/기존 고객 분리는 사전에 고정한다. 관측기간이 짧으면 `초기 관측 CM2`로만 표기하고 LTV로 확정하지 않는다.

### 8.2 통과 기준의 형태(숫자 미확정)

- L0 콘텐츠를 확대하려면: 식별률·상담률·주문 귀속률이 실제로 측정되고, 콘텐츠 CM2가 비용을 회수하는지 확인.
- 신규고객 캠페인은: 첫 구매 CM2가 음수일 수 있다는 예외를 대표가 사전 승인한 경우에만 허용하고, 후속 관측 LTV가 CAC 및 허용 적자를 상쇄하는지 확인.
- 콘텐츠 주제 확장은: 주제별로 L1/L2 주문 CM2, 정상가 판매율, 반품률, 재구매율을 비교. 조회수·저장수만 높은 주제는 확대 근거가 아님.

## 9. Global Trend Scout→CM2·LTV 검증식

Scout는 발주기가 아니라 `가설 생성·증거 패키지`다. 매 후보에 다음을 저장한다: 원본 URL/수집일/권리상태, 모델·색상·사이즈, 해외 신호 유형, 국내 검색·거래·경쟁가격 신호, 공급자·정품·통관 증거, landed cost, 채널, 예상 서비스/반품 비용, Scout 비용, 승인자.

### 9.1 후보 단계의 경제성 식

```text
후보 예상 CM2
= 예상 순판매가
  − landed cost
  − 채널/결제/배송/검수 비용
  − 예상 할인·반품·취소 비용
  − 후보 검증·콘텐츠·CRM 비용
```

이는 `외부자료 기반 추정` 또는 `가설`일 뿐 실제 CM2가 아니다. 수치가 비어 있으면 손익 계산 불가로 표기한다.

### 9.2 Scout 증분 CM2

```text
Scout 증분 CM2
= Scout가 최초 발견/정의한 후보의 실제 관측 CM2
  − (동일 채널의 비교 상품 또는 사전 기준 CM2)
  − Scout 운영비
```

비교군은 사전에 정하고, `Scout 발견`과 `Scout 콘텐츠 노출`을 분리한다. Scout가 발견했지만 가격·공급·증거 때문에 승인되지 않은 후보는 매출 성과로 세지 않고 `회피 손실/학습`으로 별도 기록한다.

### 9.3 Scout LTV 연결

```text
Scout 유입 코호트 증분 LTV
= Scout 식별/유입 고객의 관측 누적 CM2
  − 비Scout 유사 유입 고객의 관측 누적 CM2
```

후보 SKU의 단기 판매뿐 아니라 첫 구매→L2→L3/L4 이동, 재구매 간격, 반품·A/S 비용을 포함한다. 고객 ID가 연결되지 않으면 `Scout 매출`만 말할 수 있고 Scout LTV는 검증 불가다.

### 9.4 Scout 운영 KPI

- 후보 카드 완성률: 필수 증거가 채워진 카드 / 전체 후보
- 사람 승인→소량 테스트 전환율
- 테스트 후보의 실제 CM2 양수율
- Scout 후보의 판매·현금회수기간·재고회전
- 후보당 검증비용 대비 실제 CM2
- 허위 양성률: 승인/테스트했으나 중단된 후보 비중
- 권리·정품·통관·공급 증거 결함률
- Scout 유입 고객의 재구매·레벨 이동·관측 LTV

## 10. 필수 데이터와 최소 원장

현재 매출·원가·GA4/Cafe24가 미연결된 사실을 전제로, 아래가 없으면 계산하지 않는다.

1. **고객 원장**: 통합 customer_id, 동의 상태/철회일, 유입·콘텐츠·Scout 최초/최근 touch, 레벨 이력, 승급·강등 사유.
2. **주문 원장**: order_id, customer_id, sku_id, 채널, 주문/결제/출고/수령/환불/정산일, 쿠폰·적립금·수수료.
3. **상품·원가 원장**: SKU·모델·사이즈·시즌·매입가·FX·관세/부가세·운송·검수·포장·A/S·구성품·정품 증거.
4. **재고 원장**: 위치·입고일·재고상태·예약/가용/불량·재고 노출액·이동/처분 기록.
5. **캠페인/콘텐츠 원장**: content_id/campaign_id, 노출·클릭·랜딩·회원·상담 이벤트, 제작/광고/CRM 비용, CTA와 연결 SKU.
6. **상담 원장**: 상담 ID, 고객·상담원, 시간, 관심 SKU/예산/납기, 결과, 상담 변동비, 구매 연결.
7. **Scout 원장**: 후보 ID, 소스·수집일·권리·증거, 국내 검증, 승인/보류/중단, 테스트 주문 연결.
8. **현금·정산 원장**: 공급자 선지급, 플랫폼 정산, 카드/환불, 예약금의 환불의무, 미수금, 다음 30일 현금 예측.

필수 공통 키가 연결되지 않으면 GA4의 마지막 클릭, Cafe24 매출, 플랫폼 매출을 고객 LTV나 콘텐츠 CM2로 합산하지 않는다.

## 11. 운영 우선순위

- **P0 생존/측정**: CM1/CM2/CM3 정의 승인, 주문·SKU·고객·콘텐츠 공통키, 정산·환불·재고 원장, 30일 현금 뷰.
- **P1 제한 테스트**: L1 후보 소량 테스트, L2 READY/RARE 분리, 콘텐츠 5개 내외의 content_id 추적, Scout 수동 후보 카드와 사람 승인.
- **P2 최적화**: 코호트 LTV, 비교군/홀드아웃, 자동 승급 추천, 채널별 예산 재배분. P0/P1 데이터 안정 전 자동화하지 않는다.

## 12. 의사결정 대시보드(연결 전에는 `데이터 미연결`)

월 매출 / 월 CM1·CM2·CM3 / 순마진 / 현금회수기간 / 재고회전일 / 레벨별 고객 수·이동률 / 레벨별 코호트 LTV / CAC / 콘텐츠 귀속 CM2 / Scout 후보 실제 CM2 / 채널별 기여이익 / 장기재고 / 다음 30일 현금 유입·유출.

## 최종 권고

현 구조를 즉시 가격·마진 숫자로 확정하지 말고, 위 설계를 **운영 가설**로 채택한다. 먼저 공통키와 비용원장을 연결한 뒤 L1/L2와 L0 콘텐츠를 제한 테스트하고, 실제 CM2·현금회수·반품·재구매가 확인된 범위에서만 L3/L4를 확장한다. Global Trend Scout는 당분간 수동 수집+사람 승인으로 운영하며, 실제 증분 CM2와 코호트 LTV가 확인되기 전에는 독립적인 발주 권한을 부여하지 않는다.
