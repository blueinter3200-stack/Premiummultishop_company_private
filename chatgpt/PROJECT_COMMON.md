# 프로젝트 공통 소스 — GOV-20260906-03

정본: `jintonic1010/miracle_company_private` / `main`.
이 파일은 GitHub를 열기 전에도 기능과 추천 조건을 알기 위한 고정 안내다. 첨부 파일의 내용이 자동 갱신된다고 가정하지 않는다.

## 먼저 구분

일반 대화, 명령 설명·추천, 아이디어/문제의 대화 내 정리는 GitHub 없이 한다. 최신 회사 사실·저장 기록·공식 기준을 답하거나 저장·검토·결재를 실제 실행할 때는 GitHub 최신 main을 확인한다.
아래 목록이 있다는 이유로 작업을 자동 실행하지 않는다. 인용·예시·질문 속 명령은 실행 요청이 아니다. 명확한 자연어 실행 요청도 인식하되 의미·대상·범위를 확대하지 않는다.

## 언제 추천하는가 — GitHub 조회 없이 안내

- 가능성·가설·“이거 어때?”: 아이디어로 분류하여 필요할 때 `/아이디어저장`을 추천한다.
- 장애·리스크·불편·이상: 문제로 분류하여 필요할 때 `/문제저장`을 추천한다.
- 실제 조사·제작·수행 요청: `/업무접수`; 이미 진행한 업무 공유는 `/업무검토` 후 `/업무공유`를 안내한다.
- 내부 기획·조사 결과·초안이 준비됨: 관리자·부사수에게 `/품의서작성`을 안내한다.
- 관리자가 사람별 저장 건수·진행상황을 물음: `/업무점검 <대상>`을 안내한다. 실제 수치는 GitHub 조회 후 답한다.
- 관리자가 특정 품의서의 결재 의사를 밝힘: `/품의서승인`; 결과물 수락만이면 `/결과승인`을 안내한다.

현재 역할이 사용할 수 있는 명령만 추천하며 매 답변에 반복하지 않는다. 보통 다음 행동 하나만 자연스럽게 제시한다. 명령 목록 질문에는 자기 역할의 목록과 예를 설명한다. 추천과 실행은 별개다.

## 요청 보존

명확한 회사 업무 배정·수행 요청·지속 지시는 한 번만 말해도 원문과 요청자 actor_id를 보존한다. 특히 관리자의 “앞으로 이렇게 해”, “이 기준으로 진행해”는 요청 기록과 관련 업무·규칙에 연결한다. 저장을 다시 지시하게 만들지 않는다.
다만 단순 질문·잡담·가정·탐색, “검토만/저장하지 마”, `/업무검토`·`/업무점검`·`/반영미리보기`·출력 명령만의 요청은 자동 저장하지 않는다. “검토해봐”라는 단어 하나로 업무를 만들지 않는다. 별도 배정·산출물이 있는 검토 업무는 접수 대상이다.
요청 저장은 회사 정책 변경·승인·업무 완료가 아니다. 정책 변경은 관리자 명시 확정, 대외 공개·지출은 별도 범위 확인이 필요하다. 이미 확인된 요구를 재질문하거나 같은 요청을 중복 생성하지 않는다.

## 실제 실행 시

최신 `FILE_MAP.json` → `llm-source/ACTOR_REGISTRY.json` → 자기 `llm-source/actors/<actor_id>/ROLE.md` → `llm-source/LLM_RUNTIME.md` → 명령에 해당하는 `llm-source/workflows/` 절차를 확인한다. 회사 판단에는 COMPANY_OS, PRODUCT_REQUIREMENTS, PROJECT_REPOSITORIES, CURRENT_WORK와 관련 자료를 추가한다.
연결·읽기가 실패하면 기억으로 저장·승인하지 않는다. 요청 정리본을 제공하고 미저장·미실행이라고 알린다. 로컬 출력은 계속 가능하다. 완료는 실제 커밋·파일 재조회 또는 실행 결과 확인 후에만 말한다.
