# 세 프로젝트 설치 — GOV-20260906-05

이번 판은 업무 검토→요청→관리자 결정→진행 갱신과 결정 알림을 도입한다. 옛 운영 지침·역할 소스와 함께 적용하지 말고 교체한다. 일반 업무자료는 삭제하지 않는다.

## 지침 칸
각 chatgpt/admin, representative, assistant의 PROJECT_INSTRUCTIONS.md 본문만 해당 프로젝트 지침 칸에 넣는다. 파일 자체를 소스에 중복 업로드하지 않는다.

## 첨부 소스
세 프로젝트 공통: chatgpt/PROJECT_COMMON.md, llm-source/ACTOR_REGISTRY.json.
관리자: llm-source/actors/ACT-001/ROLE.md.
대표님: llm-source/actors/ACT-002/ROLE.md.
부사수: llm-source/actors/ACT-003/ROLE.md 및 RULES.md.
다른 actor ROLE을 섞지 않는다. 상세 workflow·현재 업무·결정·INBOX 전체는 상시 첨부하지 않는다.

## 업데이트 최소화
정체성·허용 명령·추천 조건·요청 보존·알림 확인 시점 같은 로컬 행동 원칙만 고정한다. 업무·데이터 증가, 내부 서식·상태판·조회 간격·실패 처리 변경은 최신 GitHub에서 읽으므로 통상 프로젝트 교체가 필요 없다. 단, 역할/권한·명령·GitHub 조회 전 행동·진입 경로가 바뀌면 관련 고정 소스를 교체해야 한다. 첨부가 자동 갱신된다는 뜻은 아니다.

## 확인
명령 설명과 출력에는 GitHub 조회가 없어야 한다. 업무요청은 유효한 검토 후 제출하되 W를 만들지 않아야 한다. 관리자 승인에 업무 시작 범위가 있을 때만 W를 만들거나 연결해야 한다. 대표님/부사수의 결정 명령은 거부돼야 한다. 구명령과 별칭은 실행되지 않아야 한다.
보류→승인/반려는 새 D와 작성자 알림이 생성돼야 한다. 읽기 전용에서는 표시 영수증도 쓰지 않는다. 같은 건 검토는 과거 사유를 보되 전체 옛 이력을 불필요하게 읽지 않는다.
스크립트·구조 테스트는 실제 세 프로젝트 설정, LLM 매번의 행동, 실시간 푸시·독립 인증을 검증하지 않는다. GitHub main 반영과 실제 프로젝트 설정 교체는 별개다.
