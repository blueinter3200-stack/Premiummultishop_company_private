# 세 프로젝트 설치 — GOV-20260907-01

이번 판은 업무계획안 명령과 구두 요청 직접 제출, 관리자 채택/배정/계획실행 분리, 작업지시 알림을 반영한다. 세 프로젝트의 기존 운영 지침과 소스를 교체한다. 일반 업무자료는 삭제하지 않는다.

## 지침과 소스
각 chatgpt/admin, representative, assistant/PROJECT_INSTRUCTIONS.md 본문은 해당 프로젝트 지침 칸에 붙인다. 파일 자체를 소스에 중복 업로드하지 않는다.
공통 첨부는 chatgpt/PROJECT_COMMON.md와 llm-source/ACTOR_REGISTRY.json이다. 관리자 ACT-001/ROLE.md, 대표님 ACT-002/ROLE.md, 부사수 ACT-003/ROLE.md 및 RULES.md를 자기 프로젝트에만 추가한다. 다른 사람 ROLE을 섞지 않는다.
상세 workflow·현재 업무·INBOX·전체 요청 원문을 고정 소스로 복사하지 않는다. 소스는 GitHub 없이 기능을 알고 추천하게 하고, 실제 저장/결정/수행은 최신 원격 기준을 확인한다.

## 사용 전 확인
대표님 구두 요청을 기록한 부사수가 별도 업무요청 없이 업무계획안까지 제출할 수 있는지 확인한다. 제출만으로 W나 본 작업 허가가 생겨서는 안 된다. 업무결정 승인에서 부사수 배정·관리자 직접 수행·담당 미정을 구분한다. 나중 배정/재배정에는 새 작업지시 사건이 필요하다.
배정 알림을 한 번 안내한 후에도 미완료 작업지시는 자기 조회판에 남아야 한다. 계획안 결의는 정확한 버전·담당·범위만 허가하고, 본 작업 전 최신 승인 확인을 생략하지 않는다. 대표님의 다른 미배정 요청을 부사수가 전수 조회하지 않는지 확인한다.
이전 명령·별칭은 실행하지 않는다. 읽기 전용/저장 금지는 표시 영수증도 쓰지 않는다. 실제 표시와 사용자의 확인은 구분한다.

## 변경을 최소화하는 경계
정체성·허용 명령·추천·구두 요청·작업지시 인식 같은 로컬 행동은 고정한다. 업무 데이터·내부 서식·조회 주기·실패 처리만 바뀌면 최신 GitHub를 읽어 통상 재설치하지 않는다. 역할·명령·로컬 원칙·진입 경로 변경에는 해당 고정 파일 교체가 필요하며 첨부는 자동 갱신되지 않는다.
패키지는 scripts/build_chatgpt_package.py로 정본 바이트와 소스 커밋을 연결한다. SOURCE_MANIFEST와 체크섬은 검증용이며 프로젝트 소스에 넣지 않는다.
실제 프로젝트 설정 교체·실사용 LLM 동작·계정별 접근제어·실시간 푸시 설치는 GitHub 저장이나 로컬 테스트로 완료했다고 주장하지 않는다.
