## 1. 한 줄 결론

**제한 실행.** 1차 개발은 착수하되 착수 순서를 “AI/자동화”가 아니라 **데이터 파이프라인 + Customer Master**로 고정한다.

문서의 이유: 2026-08-01 이후 매출·재고·고객 실데이터 파일 0건(최종 실측 2026-08-10)이며 KPI 기준선이 없어, AI Layer를 먼저 만들면 실제 사용이 불가능할 위험이 큼.

### 3-3. ‘지금 살 가치’ 판정 6기준

Product Master 필드로 요구하며 하나라도 없으면 추천 대상에서 제외.

1. 가격 가치 — 경쟁사 가격 대비 실질 합리성
2. 상품 가치 — 시즌·수요·활용도·희소성
3. 재고 가치 — 실제 구매 가능 재고 + 확인 시각(timestamp)
4. 시간 가치 — 국내재고 여부·출고일·배송예정일
5. 신뢰 가치 — 정품·구매경로·통관·구성품·검수 범위
6. 서비스 가치 — 상담·피팅·픽업·수선·세탁·관리 가능 여부

### 3-4. 큐레이션 태그 / 금지 표현

허용 태그: 오늘의 가격 기회 / 국내 즉시출고 / 공급처 비교 완료 / 소량 확보 상품 / 매장 실물 확인 가능 / 재입고 불확실 / 지금 구매 추천 / 가격 변동 주의

금지 표현(증빙 전 하드스탑): **최저가 / 공식 / 독점 / 100% 정품**. 자동생성 템플릿에서 원천 차단하도록 요구.

## 4. 시스템 아키텍처와 설계 원칙

고객·상품·재고·주문·상담·배송·반품 데이터
→ PMS Core(Customer/Product/Order/Inventory Master)
→ Rule Engine
→ Automation Engine
→ AI Layer
→ Cafe24 / 카카오 / 물류 / Realpacking / 관리자 Dashboard

설계 대원칙:
1. AI는 주문금액·재고수량·환불금액·판매가격을 직접 변경하지 않으며 후보만 생성, 실제 변경은 Rule Engine 수행.
2. 모든 상태 변화는 audit log로 기록.
3. 미확인 값은 비워두고 UNVERIFIED 처리, 추정치를 실측 필드에 입력 금지.
4. 읽기/쓰기 분리. 1차 외부 API는 읽기 전용, 쓰기는 3개월 무사고 후 재검토.

## 6. 개발 범위 — 코어 모듈 요구사항

- **Customer Master(최우선)**: Cafe24·POS·ERP·매장고객·카카오를 1인 1ID로 통합. 확실한 식별자 일치 시만 자동 병합, 애매하면 MERGE_REVIEW. DoD는 고객 10명 샘플의 4개 소스 이력 1화면 통합 + 중복률·수신동의율 산출.
- **Product / Inventory Master**: PMS Domestic Stock과 Global Supply Stock 분리. 재고 상태는 입고→판매가능→예약→피킹→포장→출고. §3-3 6기준과 공급가·관세·부가세·국제/국내운송·수수료·반품충당 필드 요구. DoD는 동일 SKU 자사몰 표시재고=Master 판매가능재고, 3일 연속 오차 0.
- **OMS**: Cafe24 결제완료→PMS Order→상품·옵션 검증→재고 Lock→국내/글로벌 판별→출고/공급처 주문→송장→Cafe24 상태 갱신→배송안내. DoD는 수기 재입력 0건, 주문 전 이력 조회.
- **WMS + Realpacking**: Scan→바코드→일치확인→검수→촬영→포장→송장→출고. 누락 시 SHIPMENT_HOLD. DoD는 Realpacking 누락 0.
- **RMA**: 반품요청→사유→회수→입고→검수→판정→환불/교환→Customer Master. 사유코드 필수. DoD는 주문번호 기준 단일 추적과 사유코드별 자동 집계.
- **CRM Trigger Engine**: 브랜드 신상품, 사이즈 재고, 가격 10% 하락, 장바구니 이탈, 90일 미구매, VIP 신규, 재입고, 한정재고, 구매완료, 반품완료 이벤트 후보. 수신동의 미확인/재고 0·미확인/순마진율 12% 미만/21:00~08:00/(광고) 누락 시 발송 불가. 발송은 사람 승인 후 실행.
- **관리자 Dashboard**: 고객·상품기회·주문·서비스·수익을 대표 1화면에 표시. 미연결 지표는 수치 추정 없이 “데이터 미연결”.
- **CS 통합**: 고객정보·구매이력·주문·배송·Realpacking·반품·관심브랜드·추천상품을 상담원 1화면에 표시. AI는 초기 직접 응답이 아니라 직원 보조.

## 7. Revenue SEO OS — 개발 요구사항

SEO를 유입 업무가 아니라 소싱·판매 판단용 데이터 센서로 운영.

Google·Naver·쇼핑몰·경쟁사 데이터
→ Trend Agent
→ Keyword Agent
→ Sourcing Agent
→ Profit Agent
→ Decision Engine(S/A/B/C/D)
→ Content Agent
→ Cafe24 승인 등록
→ Google Search·Merchant Center·Naver
→ 주문·매출·기여이익
→ 카카오 CRM·재구매
→ 다음 소싱 판단으로 환류.

### 단계
1. 기술 SEO: 대표 URL, canonical/내부링크/sitemap 일치, Search Console 색인, robots.txt 결함 수정, Product·Breadcrumb 구조화 데이터, JSON-LD 충돌, Merchant Center 정합성.
2. 돈 되는 상품키워드: `검색수요 × 구매의도 × 예상 기여이익 × 공급가능성 × 재고회전 ÷ (경쟁강도 × 가격리스크 × 반품리스크)`는 방향 모델. 실제 순이익·순마진율·회수기간은 SKU별 입력값으로 계산하고 LLM 추론 금지.
3. 콘텐츠→상품 퍼널: 카테고리 추천→비교→브랜드 카테고리→상품 상세→구매→카카오 CRM·재구매. KPI는 콘텐츠→상품 클릭, 상품상세 전환율, SEO 유입 주문/기여이익, CRM 재구매율이며 조회수는 KPI 아님.
4. 상품페이지 SEO 자산화: SEO 상품명, Meta Title/Description, 설명, FAQ, ALT, 관련상품, 내부링크, Product·Offer·Breadcrumb Schema. Product Master 확인 사실만 사용.
5. Merchant Center: 식별자·상품명·브랜드·가격·재고·이미지·배송·반품·랜딩URL·페이지 데이터 일치 자동 검증. API 오류/가격불일치/품절/정보누락/승인거절/정책위반 가능성/canonical 불일치 시 자동전송·광고 보류.

## 8. 자동화 권한 3단계

| Level | 의미 | 예시 |
| --- | --- | --- |
| L1 자동 | 위험 낮음 | 재고차감·등급계산·로그·리포트 |
