# 프리미엄멀티샵 Revenue OS v7.0 — Codex 상시 작업 규칙

## 아이디어

프리미엄멀티샵의 Codex CLI 작업 환경에 `AGENTS.md`를 상시 규칙으로 두고, Codex가 단순 조언 도구가 아니라 대표님의 실행 에이전트로서 허용 범위 안에서 자료 수집 → 계산 → 초안 작성 → 검증 → 보고까지 수행하도록 운영한다.

핵심은 데이터 신뢰성, 수익성 하드스탑, 승인 단계, 재현 가능한 계산, 노트 작성 규칙, 정형화된 보고 형식을 하나의 운영 규칙으로 고정하는 것이다.

## 주요 운영 규칙

### 데이터 원칙
- 없는 숫자를 만들지 않고 추정은 `[전제]`, 확인 불가는 `[검증 불가]`로 표시한다.
- 모든 인용에 출처 파일 경로와 기준일을 붙인다.
- `60_Data/`는 읽기 전용으로 두고 덮어쓰지 않는다.
- 계산 결과는 `.py` 스크립트로 재현 가능하게 만든다.
- 약어는 첫 등장 시 한국어 뜻과 함께 표기한다.

### 하드스탑
다음 기준 중 하나라도 위반하면 결론을 `보류` 또는 `중단`으로 제한한다.
- 월 순이익 500,000원 미만
- 순마진율 12% 미만
- 회수기간 6개월 초과
- 리드타임 45일 초과
- 재고회전일 90일 초과
- 데이터 신뢰도 0.70 미만
- 법적 안전도 5점 만점 중 4점 미만
- 정품·통관·상표·A/S 책임 불명확
- 투자금이 가용현금의 30% 초과

검사는 `.codex/scripts/hardstop_check.py`로 실행하고 수기 판단하지 않는 구조를 제안한다.

### 승인 매트릭스
- 자동 실행 가능: 내부 자료 정리, 데이터 분석, 보고서 생성, 이상징후 알림, 승인된 템플릿 초안, 사전 허용 범위 데이터 업데이트
- 승인 후 실행: 고객 공식 메시지, 거래처 조건 발송, 판매가 변경, 광고예산 변경, 상품 공개·판매 시작, 환불·보상 승인
- 대표 명시적 승인 필요: 발주, 송금, 계약, 법적 책임 인정, 신규 공급자 계좌 등록, 3,000,000원 초과 투자, 5% 초과 가격 인하, 개인정보 외부 전송, 데이터 삭제, 인사조치

승인이 필요한 작업은 직접 실행하지 않고 `70_Reports/승인대기/`에 초안을 만든 뒤 보고하도록 한다.

### 노트 및 보고 표준
- 파일명은 `YYYY-MM-DD_유형_대상.md` 형식
- 신규 노트는 `90_Templates/` 템플릿의 frontmatter 구조 사용
- 내부 링크는 `[[파일명]]`
- 신규 개념은 링크만 만들고 빈 노트는 자동 생성하지 않음
- 태그는 `99_Meta/태그사전.md`에 등록된 것만 사용
- 모든 보고는 한 줄 결론, 에이전트 판단, 실행 결과, 액션, 누락 데이터, 다음 점검일 구조로 통일
- 액션에는 담당자·마감일·KPI·승인 여부를 명시

### 자주 쓰는 명령 후보
- `/inbox`: `00_Inbox` 전량 분류 후 이동
- `/hardstop <파일>`: 하드스탑 9종 검사
- `/weekly`: 주간 보고서 생성 후 `70_Reports/` 저장
- `/supplier <업체명>`: 공급처 검증 노트 초안 생성
- `/link`: 고아 노트 탐지 및 연결 제안

세부 프롬프트는 `.codex/prompts/`에서 관리하는 구조다.

## 목적 / 기대효과

- Codex 작업을 매 세션 동일한 운영 원칙으로 통제한다.
- 수익성·법적 위험·데이터 신뢰도가 낮은 안을 자동으로 걸러낸다.
- 자동 실행과 승인 필요 작업의 경계를 명확히 해 고위험 작업의 무단 실행을 막는다.
- 계산과 판단을 스크립트 기반으로 재현 가능하게 만들어 검증성을 높인다.
- 대표님이 최종 보고만 보고도 실행 여부를 빠르게 판단할 수 있는 정형화된 운영 체계를 만든다.
