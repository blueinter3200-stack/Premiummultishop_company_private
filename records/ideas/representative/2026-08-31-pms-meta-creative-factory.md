# PMS Meta 광고 Creative Factory — 승자 소재 반복 생산 구조

## 아이디어

Premium MultiShop(PMS)의 광고 운영을 단순 광고 세팅 중심이 아니라 **고객을 멈추게 만드는 콘텐츠와 명확한 가설 기반 테스트 중심**으로 전환한다.

핵심 반복 구조는 다음과 같다.

`SKU → 고객문제 → 광고소재 → 테스트 → 승자 → 복제 → 확대`

상품 데이터에서 판매량·마진·재고를 확인해 광고할 SKU를 선정하고, 고객 리뷰·문의·검색어·카카오 상담 등에서 고객의 Pain Point(고객의 불편·고민)를 추출한다. AI는 Pain Point별 Hook(첫 시선·관심을 잡는 문구), 영상 Script(대본), 이미지·UGC(사용자 제작형 콘텐츠)·Reels(짧은 세로형 영상) 소재를 생성한다. Meta에서 소액으로 테스트한 뒤 CTR(클릭률), CPC(클릭당 비용), CVR(구매 전환율), CPA(구매 1건당 광고비), ROAS(광고비 대비 매출)와 광고 후 기여이익을 기준으로 판정한다. 승자 패턴이 확인되면 AI가 변형 소재를 추가 생성해 다시 테스트·확대하는 반복 루프로 운영한다.

## 운영 원칙

- 광고 성과의 핵심을 세밀한 타겟팅이나 CBO/ABO 세팅 자체보다 콘텐츠 기획과 고객 이해에 둔다.
- 좋은 소재는 `메시지 + 비주얼 + 제안(Offer)` 구조로 설계한다.
- 제품 특징보다 고객의 문제·사용 상황·욕구·변화·증거를 먼저 보여준다.
- 첫 3초 안에 고객이 “내 문제”라고 인식할 수 있는 Hook을 우선 테스트한다.
- 한 번에 여러 변수를 바꾸지 않고 `가설 → 한 변수 테스트 → 데이터 확보 → 판정 → 다음 가설` 순서로 운영한다.
- ABO(광고세트별 예산 직접 배분)는 공정한 실험 목적, CBO(캠페인 전체 예산 자동 배분)는 검증된 구조의 확대 목적에 활용할 수 있으나 절대 규칙으로 고정하지 않는다.
- 작은 광고 예산에서는 대형 광고주의 복잡한 캠페인 구조를 그대로 복사하지 않고 데이터가 충분히 모이도록 구조를 단순화한다.

## PMS 광고 소재 기본 구조

`HOOK → PROBLEM → PROOF → PRODUCT → PRICE → CTA`

예시 방향:
- HOOK: “백화점 가격 때문에 포기했던 가방이라면 가격부터 비교하세요.”
- PROBLEM: 국내 백화점 가격, 해외가격, 정품 불안, 사후서비스 걱정
- PROOF: 정품 보증, 실물 검수, 수입 이력, 실제 매장, 사후서비스·수선
- PRODUCT: 실제 상품 공개
- PRICE: 비교 가능한 가격 또는 구매 혜택
- CTA(행동 유도): 재고 확인, 카카오 상담, 구매

PMS에서는 단순히 “싸다”는 메시지보다 **가격 + 정품 신뢰 + 사후책임**을 핵심 차별화 포인트로 사용한다.

## 테스트 설계

처음부터 소재를 대량 생성하기보다 다음처럼 구조화한다.

- SKU 1개
- 고객 문제/Angle(광고 관점) 3개
- Angle별 Hook 3개
- 총 9개 수준의 초기 소재로 시작

예시:
- 가격 관점: “백화점 가격과 비교해 보세요.”
- 정품 신뢰 관점: “온라인 명품 구매가 불안한 가장 큰 이유.”
- 희소성 관점: “다시 들어올지 모르는 이번 재고.”

이 구조로 어떤 심리적 메시지가 실제 클릭·구매·기여이익을 만드는지 확인한다.

## 성과 판정 기준

Meta 광고 소재별로 최소 다음 데이터를 연결한다.

- Spend(광고비)
- CTR(클릭률)
- CPC(클릭당 비용)
- 구매 CVR(구매 전환율)
- CPA(구매 1건당 광고비)
- ROAS(광고비 대비 매출)

다만 PMS에서는 ROAS만으로 성공 여부를 판정하지 않는다.

`광고 후 실제 기여이익 = 매출 - 상품원가 - 결제수수료 - 배송·포장 - 반품예상비 - 광고비`

최종 판정은 `ROAS → 광고 후 기여이익 → 순이익` 순서로 강화한다.

## 목적 / 기대효과

- 광고팀을 “광고 세팅팀”에서 **승자 소재를 반복 생산하는 콘텐츠 실험팀**으로 전환
- 광고 운영의 감각 의존도를 낮추고 가설과 데이터로 의사결정
- 적자 광고와 허수 ROAS를 조기에 제거
- 상위 SKU에 테스트 예산을 집중해 학습 속도 향상
- 고객 문제·광고 소재·매출·기여이익 데이터를 연결해 Revenue OS(매출 운영체계)의 학습 루프로 축적
- 타겟·입찰·예산배분 등 자동화 가능한 운영은 AI에 넘기고 사람은 고객 이해와 콘텐츠 전략에 집중

## 관련 업무

- 최근 Meta 광고 소재 데이터 수집 및 유형 분류
- 소재별 기여이익 계산
- 상위 SKU 선정
- SKU별 고객 문제/Angle 정의
- Hook 및 영상·이미지 소재 생성
- 한 변수씩 A/B 테스트
- 승자 소재 확대 및 변형 소재 자동 생성
- 실패 소재 자동 중단 기준 설계
- PMS Revenue OS와 광고 데이터 연결

## 아직 미정인 부분

- “최소 50개 전환” 같은 고정 최적화 기준은 PMS 공식 규칙으로 확정하지 않음
- 계정·목표·전환 이벤트·CPA에 따른 테스트 종료 및 승자 판정 수치는 별도 설계 필요
- ABO/CBO 사용 기준은 절대 공식이 아니라 계정별 예산·데이터량에 따라 결정
- 광고 자동 생성·자동 중단·자동 확대의 구체적인 승인 범위와 자동화 수준은 추후 확정 필요
