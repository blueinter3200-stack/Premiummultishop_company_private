# 선택적 결정 알림·상태함 — GOV-20260906-05

## 정본과 파생물
D-ID가 결재 정본, R/SUB/W가 대상 정본이다. `records/notifications/<actor_id>/<N-ID>.json`은 결정 사건에서 파생한 통지 이벤트이며 N-ID=N-<D-ID>-<actor_id>로 같은 사건/수신자의 중복을 막는다.
`records/notification-receipts/<actor_id>/<N-ID>.json`은 실제 대화 표시/사용자 확인 영수증이다. `records/inbox/<actor_id>.json`, `records/decision-views/<actor_id>.json`, `records/DECISION_INDEX.json`은 조회판이다. 원본을 승인함/보류함/반려함으로 이동하지 않는다.
수신자는 해당 요청자·품의 작성자와 직접 관련 담당자만이다. 개인정보·관리자 비공개 메모를 공통 INBOX로 복사하지 않는다. actor별 폴더는 논리적 구분이며 실제 계정 접근제어를 대체하지 않는다.

## 확인 시점과 비용
기본: 새 대화에서 첫 실제 회사 업무, 같은 요청/품의/업무 재개, 업무검토·업무요청·품의서작성·업무업데이트의 진입, 명시적 최신 결정 조회 때 자기 INBOX 하나를 확인한다. 일반 잡담·명령 안내·로컬 출력에는 읽지 않는다.
같은 연속 업무 흐름에서는 조회한 inbox revision과 표시 N-ID를 대화 내에서 재사용한다. 기본 30분 이내 동일 흐름 재조회는 생략하되 새 대상 재개/사용자 최신 확인 요청은 새로 조회한다. 시간이 흘렀다고 스스로 백그라운드 조회하지 않고 다음 사용자 업무 행동 때 판단한다. 시각을 모르면 시간 경과를 추정하지 않고 업무 문맥 경계를 사용한다.
핵심 실행/결정/업무업데이트 직전에는 대상 최신 D·버전·범위를 직접 확인한다. 작은 INBOX 캐시나 조회 생략 규칙을 승인 우회의 근거로 쓰지 않는다.
INBOX 기본 페이지는 최신 유효 미전달 사건 최대 20개, 사용자 표시는 관련/최신 최대 3개와 나머지 건수다. 초과는 more_count와 다음 페이지 포인터로 보존하고 무음 삭제하지 않는다. 결정 원문은 필요한 이벤트만 추가 조회한다.

## 새 사건만 알림
새 D의 의미 있는 상태/조건 변화만 통지한다. 이전 릴리스의 옛 반려·보류를 처음부터 전부 unread로 만들지 않는다. 같은 사건 재시도나 같은 결정을 다시 읽는 것은 새 알림이 아니다.
동일 대상/내용 버전/범위에 후속 결정이 있으면 과거 unread 사건은 superseded로 조회에서 접고 최신 유효 변화만 보여준다. 예: 미확인 보류 뒤 승인되면 '보류→승인'만 안내한다. 원래 N/D는 감사 이력에 보존한다. r1 반려를 r2 반려라고 표시하지 않는다.
알림 예: '요청 R-… r2가 보류에서 승인으로 변경됐습니다. 승인 범위: 조사. 결정 D-…'. 이유·대상 버전·다음 행동을 짧게 표시한다. 비승인 상태는 진행 허가가 아니다.

## 표시와 확인·중복 방지
fetch만 했으면 unread다. 사용자에게 실제 대화로 해당 N-ID 내용을 표시한 후에만 delivered_at와 표시 근거를 영수증에 남긴다. 사용자가 확인했다는 명시적 응답이 있어야 acknowledged_at이다. 자동 표시를 사람의 읽음/동의로 주장하지 않는다.
현재 명령이 쓰기를 허용한 업무 처리이거나 사용자가 알림 확인 기록을 명시한 경우, 이미 실제 표시한 N-ID만 영수증과 INBOX에 함께 반영한다. 아직 표시하지 않은 나머지는 unread다. 확인 기록 실패는 미기록으로 보고한다.
업무검토/업무점검/반영미리보기/출력·'저장하지 마'는 영수증도 쓰지 않는다. 이때는 대화 내 표시 목록으로 반복을 막고, 다음 허용 쓰기/명시적 '알림 확인했어' 때 해당 표시분만 기록한다. 영속 영수증이 없으면 다른 새 대화에서 재표시될 수 있다. 무손실 알림과 전역 정확히 한 번 표시를 현재 채팅 도구만으로 보장한다고 말하지 않는다.
보류 자체를 주기적으로 반복 독촉하지 않는다. 별도 합의된 리마인더가 없으면 시간 경과만으로 새 N을 만들지 않는다. delivered/acknowledged는 승인·수행 완료와 무관하다.

## 이력 조회와 별개
같은 건 재검토에는 알림 전달 여부와 관계없이 현재 held/rejected와 과거 이유를 확인한다. 새 후보에는 직접 같은 목적/범위의 결정만 선택한다. 당시 이유·현재 차이·해소 근거를 보고하며 과거 반려를 인격 평가나 영구 차단으로 취급하지 않는다. 계속 유효한 제한은 별도 관리자 공식 근거를 연결한다.

## 운영 방식
결정 저장 시 helper가 이벤트·상태함·INBOX의 변경 집합을 만든다. 연결된 GitHub 도구로 동일 커밋 저장 후 재조회한다. 이 절차는 실제 채팅방 설정 교체·푸시 서버·메일/n8n 연결이 아니다. 사용자가 다음 관련 업무 대화를 할 때 조회·안내하는 방식이다.
