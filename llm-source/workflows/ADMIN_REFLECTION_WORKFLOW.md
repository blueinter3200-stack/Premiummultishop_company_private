# 관리자 결과 수락·회사 기준 반영 — GOV-20260906-05

업무요청/품의서의 승인·수정요청·보류·반려는 DECISION_WORKFLOW로 분리한다. 이 문서는 반영미리보기, 결과승인, 기준확정, 아이디어반영, 문제반영의 절차다.

## 반영미리보기: 공통, 읽기 전용
특정 기록 또는 현재 문맥의 단일 대상을 원문·정제본·COMPANY_OS/PRODUCT_REQUIREMENTS/PROJECT_REPOSITORIES/CURRENT_WORK·관련 결정/부서 기준과 대조한다. 구현 주장은 실제 구현 저장소를 확인한다. 현재 확정, 예상 변화, 충돌, 미확인, 관리자 결정 필요를 나눈다. 파일·요청·목차·원장·알림 영수증을 쓰지 않는다.

## 결과승인: ACT-001
실제 산출물 ID·버전·내용/해시와 해당 승인 조건·근거를 검토한다. 명확한 수락만 deliverable 범위의 불변 D로 남긴다. 제작·게시·비용·정책 변경이나 업무 전체 완료를 자동 포함하지 않는다. 품의의 실행계획 결정과 산출물 수락은 다르다. 반려/수정이 필요한 품의는 품의서결정에 명확한 결과를 사용한다.

## 기준확정: ACT-001
앞으로 반복 적용할 회사 정책·요구사항만 명시된 범위로 확정한다. 회사 기준 개정과 업무 시작 허가는 다르다. 요청 원문·현재 기준·변경안·근거·영향·미확인을 검토하고 policy_change D와 requirement-changelog를 남긴다. 구기준은 정본에서 새기준으로 대체하되 과거 기록은 보존한다. 단순 결과물 수락을 COMPANY_OS에 누적하지 않는다.

## 아이디어반영·문제반영: ACT-001
record_id·author_id·원문·필요 정제본·현재 기준·관련 업무·PENDING_INDEX를 대조한다. 작성자가 대표님/부사수/관리자인지 유지하고 선택한 개별 기록의 채택 범위만 반영한다. 실제 원문을 상태 폴더로 옮기지 않는다.
성공 후 아이디어는 reflected/reflected_at/decision_ref를 연결하고 pending에서 제거한다. 문제 해결 방향은 reflected, 실제 해결 증거까지 확인돼야 resolved다. 참고·정제·검토는 공식화가 아니며 자동 pending 제거를 하지 않는다.

## 공통
실제 관리자 발언과 정확한 대상 버전·범위·이유를 D에 남긴다. 기존 D는 덮어쓰지 않고 변경/철회도 새 D로 연결한다. 다른 사람의 승인 전달은 근거가 아니다. 의사결정에 직접 영향을 받는 작성자에게 새 사건 통지는 INBOX_WORKFLOW를 적용하되 과거 이력을 소급 방송하지 않는다.
대상 정본·기록 상태·인덱스·필요 조회판·결정과 통지를 같은 커밋으로 처리한다. 실패 시 pending만 먼저 제거하지 않는다. 명확한 현재 관리자 검토·반영 복합 지시는 순차 수행 가능하나 미지정 범위를 확대하지 않는다. COMMON_IO 재조회 후 완료를 보고한다.
