# 관리자 결재·공식 반영 및 반영미리보기 — GOV-20260906-03

## 반영미리보기 — 세 역할의 허용 범위, 읽기 전용

`/반영미리보기`는 현재 지정 기록 또는 방금 저장한 명확한 기록을 대상으로 한다. 모호하면 PENDING_INDEX의 관련 항목만 찾아 선택한다.
대상 원문·필요 정제본·COMPANY_OS·PRODUCT_REQUIREMENTS·PROJECT_REPOSITORIES·CURRENT_WORK·관련 부서 기준을 읽고, 구현 사실이 중요할 때만 구현 저장소를 확인한다.
현재 확정 기준, 반영 시 예상 변화, 영향·충돌, 추가 확인, 관리자 결정 필요를 구분한다. 미리보기이며 아직 공식 반영되지 않았음을 알린다. 파일·상태·인덱스·업무·승인을 전혀 쓰지 않는다.

## 관리자 전용 결재

`/품의서승인 <품의서 ID/버전> [승인|수정요청|보류|반려]`, `/결과승인 <결과물 ID/버전>`은 ACT-001만 사용한다. 구 `/품의승인`은 동일 권한의 별칭이다.
최신 main과 대상 품의서·업무·근거·결과물 버전·요청 승인 범위를 확인한다. 대상/버전/범위가 대화에서 하나로 확정되면 다시 묻지 않지만 여러 버전이면 임의 승인하지 않는다.
D-ID로 실제 관리자 발언 출처, approver_actor_id, 대상 work/submission/artifact revision, requested/granted scopes, 조건·재검토 조건·결정시각·검증 수준을 보존한다. 역할 기반 대화 승인을 독립 계정 인증·서명 확인으로 과장하지 않는다.
승인=approved, 수정요청=revision_required, 반려=rejected다. 보류 결정은 decision=held, 업무 approval_status=pending 및 보류 사유로 연결한다. 보류·반려·수정요청에는 granted_scopes를 비워 실행 승인이 생기지 않게 한다.
기존 결정은 덮어쓰지 않고 새 D-ID로 변경·취소를 연결한다. 같은 URL도 내용이 바뀌면 재결재한다. 결재 파일의 자기 참조 해시를 만들지 않는다.

## 승인 범위와 실행 분리

research=조사, production=제작, deliverable=결과물 수락, publication=특정 계정·문구·일정·버전 공개, expenditure=금액·통화·기간·사용처, policy_change=회사 기준 변경이다.
한 번에 여러 범위를 승인할 수 있지만 내용은 명확해야 한다. “초안 좋아”를 게시·비용·영구 규칙 변경으로 확대하지 않는다. 결재 기록만 만드는 명령은 외부 게시·지출을 자동 실행하지 않는다.
부사수의 승인 전달은 approval_claim이다. 실제 관리자 승인 출처와 대상·버전·범위를 확인할 수 없으면 승인대기다. 회사 정책 파일 반영은 관리자만 한다.

## 아이디어반영·문제반영

대상 record_id·author_id, 원문·필요 정제본·공식 기준·관련 업무·PENDING_INDEX를 대조한다. 명시적으로 채택한 범위의 공식 소스만 변경하고 D-ID 및 requirement-changelog를 남긴다.
아이디어는 성공 후 reflected/reflected_at/decision_ref를 기록하고 pending에서 제거한다. 문제 해결 방향 채택은 reflected, 실제 해결까지 근거가 확인된 경우만 resolved다. 정제·참고·점검만으로 이 상태를 바꾸지 않는다.
공식 반영과 대상 상태·pending 변경을 같은 커밋으로 처리한다. 실패 시 인덱스만 먼저 제거하지 않는다. 원문·actor_id·과거 귀속을 보존한다.

## 업무확정

`/업무확정`은 검토·공유된 업무 중 관리자가 채택한 회사 정책·요구사항만 공식화한다. 일반 작업 완료나 영상 수락을 전부 COMPANY_OS에 넣지 않는다.
기존 기준을 바꾸면 새 기준으로 교체해 상충 규칙을 병존시키지 않고 changelog, 결재, 업무 원장과 조회판을 함께 갱신한다. 남은 미확정은 협의 상태다. 단순히 참고한 아이디어/문제를 자동 reflected 처리하지 않는다.
현재 관리자 메시지가 검토·변경안·main 반영을 명확히 함께 요청하면 같은 작업에서 순차 검토→범위 기록→결재→반영할 수 있다. 일반 대화나 포괄적 호감 표현은 승인으로 바꾸지 않는다.
저장소 등록/제거·역할 변경은 관리자 범위이며 ID를 재사용하지 않는다. COMMON_IO에 따라 재조회한 뒤에만 완료를 보고한다.
