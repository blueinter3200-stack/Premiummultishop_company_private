# 관리자 직접 업무결정 복합 처리 — GOV-20260907-02

## 적용 조건
ACT-001이 기존 R-ID 없이 `/업무결정 승인` 또는 같은 의미의 명확한 현재 동작으로 구체적인 새 업무 내용, 완료 기준, 업무 채택을 함께 명시한 경우다. 담당 ACT-003/ACT-001/null도 실제 발언에 있는 만큼만 사용한다. 단순 “승인”, 대상이 여러 개인 답변, 인용·예시·질문, 목적/범위를 특정할 수 없는 발언에는 사용하지 않는다.
이미 현재 문맥의 실제 R-ID가 있거나 대표님/부사수 요청이 대상이면 새 관리자 R을 만들지 않고 기존 R·requester·record_owner를 그대로 사용한다.

## 순서
1. 최신 main 및 일반 원격 진입 자료를 확인한다. 이미 관련 R/D/W가 있는지 검색하여 재시도/중복을 먼저 제거한다.
2. 새 관리자 지시라면 실제 사용자 원문을 ACT-001 요청 R에 보존한다. 원문과 검토 후 current_requirements/public_summary를 구분한다. 플랫폼이 제공하지 않은 원문 시각·message id를 만들지 않는다.
3. 같은 실행에서 업무검토를 수행한다. REVISION/HOLD면 D/W/ASG를 만들지 않고 상태맵에 허용 범위만 반영한다. PASS에서만 제출/결정한다.
4. `/업무요청`을 다시 요구하지 않고 submission_status=submitted로 만든 뒤 실제 관리자 승인 D를 연결한다. 업무 채택 범위만 승인하고 계획/게시/지출을 발언보다 확대하지 않는다.
5. 같은 R에 기존 W가 없을 때만 W를 만든다. 업무 채택과 배정은 별개 필드/사건이다.
6. ACT-003 배정이 명시됐으면 실제 관리자 지시 텍스트와 공유 가능한 brief로 ASG를 만들고 최초 N을 생성한다. ACT-001 직접 수행은 ACT-003 N이 없고, 담당 null이면 임의 배정/알림이 없다.
7. R/D/W/ASG/N/관련 기존 조회판과 `working/WORK_STATUS_MAP.json`을 하나의 변경 집합으로 만든다. 일부만 저장되면 전체 성공이 아니다.
8. main fast-forward 후 실제 커밋과 각 변경 파일을 재조회한다.

## 재시도
동일 source_event_id/원문 fingerprint의 재실행은 기존 R/D/W/ASG/N을 재사용한다. 저장 일부 누락이면 같은 ID를 복구하고 새 업무를 만들지 않는다. 다른 payload가 같은 event id를 쓰면 충돌이다.

## 경계
업무 채택 승인은 계획 준비 허용이지 ACT-003 본 작업 승인 아니다. “계획안 올려”는 planning이다. plan_execution은 특정 SUB revision 결의에서 별도로 확인한다. 관리자 ACT-001의 명시적 self_direct만 별도 계획안 없이 자기 수행을 허용할 수 있으며 그 범위는 위임되지 않는다.
