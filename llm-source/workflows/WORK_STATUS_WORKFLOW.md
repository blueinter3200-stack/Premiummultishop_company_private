# 회사 전체 업무현황 맵 — GOV-20260907-02

## 읽기와 권한
/업무진행현황은 admin/representative/assistant 공통 읽기 전용이다. 대상 생략은 회사 전체다. 사람·프로젝트·R/W-ID·상태로 제한할 수 있지만 기본값을 자기 업무로 바꾸지 않는다.
일반 호출은 최신 main의 working/WORK_STATUS_MAP.json만 읽는다. 호출 때 정본 전체 재생성·R/D/ASG/SUB/W 전수 조회·외부 저장소 조회를 하지 않는다. 로컬 고정 지침으로 명령을 설명·추천하고 실제 현황은 맵을 조회한 뒤만 답한다.
명시적 상세·최신 구현 검증은 해당 대상의 원문과 실제 관련 저장소로 확장한다. 조회는 저장이 아니며 영수증/맵도 쓰지 않는다. 없는 맵·지원하지 않는 schema·손상된 map_revision은 경고하고 기억으로 내용을 채우거나 자동으로 비공개 원문 전수 조회로 우회하지 않는다.

## 정본과 파생물
R 요청, D 결정, ASG 배정, SUB 계획안, W 수행 업무가 정본이다. 원본은 상태별 폴더로 이동·삭제하지 않는다. 맵을 편집해 승인·수행·완료를 결정하지 않는다.
W마다 한 행을 만들고, 아직 W가 없는 정식 요청/직접 제출 계획은 R 기준 행으로 표시한다. 원문 보존만 한 captured 요청을 정식 승인대기로 만들지 않는다. W가 생긴 원 요청은 W행에 연결하며 같은 일의 R/SUB를 여러 업무로 세지 않는다. 완료·반려·보류 행을 무음 삭제하지 않는다.
request_decision, assignment_status, plans, effective_plan_status, work_status는 별도 축이다. 새 계획 r2 대기/반려가 승인된 r1을 자동 철회하지 않는다. 내용 버전/hash가 변하면 옛 승인을 현재 승인으로 표시하지 않는다. legacy 승인 근거가 부족한 건은 legacy_unverified/needs_redecision로 구분한다.

## 공용 요약과 비공개 원문
세 역할은 회사 전체의 공용 현황을 본다. 이것은 미배정 대표 요청 원문·관리자 결재 메모·개인정보 접근권이 아니다. 미승인 요청의 공개용 제목/최근 요약/다음 행동/차단 요약은 public_summary의 허용 필드로만 제공한다. 요약 미제공은 ID·단계와 “업무요청 (원문 비공개)”로 남긴다. 기존 CURRENT_WORK에 이미 공개된 W 제목은 유지한다.
raw original_text, private_notes, approval_source, reason 원문, 자료 본문, 개인 INBOX는 맵에 복사하지 않는다. 담당자는 자신의 승인된 범위 안에서 사실·기밀 여부를 검토한 공용 요약만 갱신한다. 구조적 필드 검사는 개인정보 자동 판별/계정 ACL 구현을 의미하지 않는다.

## 쓰는 시점
요청 제출/직접 계획 제출/관리자 업무결정/계획 결의/배정·재배정/계획준비·실행 업데이트/완료/관련 R 변경을 저장할 때 정본과 맵을 같은 커밋에 넣는다. scripts/decision_flow.py의 render 경로가 scripts/work_status.py를 호출한다. RC나 수동 정본 수정도 COMMON_IO에서 work_status.py finalize 또는 build/check를 적용한다.
전체 저장소가 로컬에 있을 때 생성기는 JSON 원장을 결정적으로 스캔한다. 이 처리를 LLM이 원문을 매번 모두 읽는 것으로 바꾸지 않는다. 원격 부분 작업에서는 기존 맵과 영향받는 R/W/결정/계획/배정만 읽어 같은 산출물을 만들고, 검증 가능한 전체 snapshot에서 재생성 결과와 대조한다. 스냅샷이 불완전한데 전체 맵을 새로 만들며 기존 행을 지우지 않는다.
변경 전 최신 main/대상 blob을 확인하고 다른 작업의 행을 덮어쓰지 않는다. 동시 변경은 재검토/재생성하며 force하지 않는다. 정본만 저장되고 맵이 빠지면 부분 저장이다. 같은 ID로 복구하고 새 승인/알림을 만들지 않는다.

## 최신성·관련 저장소
records_latest_at·information_as_of·updated_at은 기록 시점이다. source_fingerprint는 정본 집합 검증용이며 외부 시스템의 실시간 최신성 증거가 아니다. 단순 /업무진행현황은 “기록된 현황”이라고 표시한다. 기록이 오래됐거나 미확인이면 그대로 드러낸다.
related_repositories는 PROJECT_REPOSITORIES에 등록된 repo/branch/purpose를 연결한다. 코드 정본은 해당 저장소에 두고 회사 저장소로 복사하지 않는다. 업무 배정이 다른 저장소 main 수정·배포·비용 승인은 아니다.
implementation_snapshots는 실제 확인한 repo/branch/commit/checked_at/status/evidence_refs/deployment_status만 기록한다. 새 확인을 하지 않았으면 기존 확인 시점을 갱신하지 않는다. commit/PR 확인과 실제 배포·업무 완료는 별개다. 여러 저장소를 하나의 원자적 커밋처럼 성공 처리하지 않는다.

## 검증과 규모
python scripts/work_status.py check <repo>는 정본에서 재생성한 맵과 저장된 맵을 비교한다. 일반 조회는 이 전체 검사를 수행하지 않는다. 지원되는 저장 절차 밖에서 파일이 바뀌면 맵이 낡을 수 있으므로 배포/커밋 검증에 포함한다.
현 규모는 단일 요약 맵이다. 행이 커지면 향후 같은 조회 진입점을 유지하며 페이지/기간별 분할과 전체 건수를 명시적으로 추가한다. “맵 하나면 무한히 적은 토큰”이라고 주장하지 않는다.
