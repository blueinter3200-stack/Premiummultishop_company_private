# 관리자 작업지시·배정 — GOV-20260907-01

## 목적과 진입
업무 채택과 누가 수행할지는 별개다. /업무결정 승인에 부사수 담당과 지시가 함께 있으면 같은 작업에서 배정한다. 이미 승인된 W에 “부사수에게 넘겨”처럼 명확한 자연어 지시가 오면 관리자 전용 assign_work 하위 절차로 처리한다. 새 슬래시 명령이나 부사수 자체 배정 권한은 추가하지 않는다.
관리자 직접 수행은 ACT-001, 부사수는 ACT-003, 담당 미정은 null이다. 미정이면 부사수 기본 배정이나 지시 알림이 없다. 직접 수행 권한을 부사수에게 자동 이전하지 않는다. 계획 작성에 관한 지시는 본 작업·게시·지출 승인과 다르다.

## 원본과 변경 사건
ASG-YYYYMMDD-NNN을 work/assignments/<ASG-ID>.json에 불변 사건으로 저장한다. W-ID, 선행 ASG, 이전/현재 담당, assigned_by_actor_id=ACT-001, 실제 instruction_text/source/locator, 원문 시점과 기록 시점, source_event_id, event_fingerprint, 승인된 brief, authorization_decision_ref, 요청 ID/내용 버전/hash를 보존한다.
승인된 brief에는 목적·범위·계획안 기대 산출물·제약과 공유 가능한 자료만 둔다. 대표님 원문 전체·비공개 메모·인사자료를 복사하지 않는다. 요청자와 지시자·수행자를 혼동하지 않는다. 기록된 출처/역할을 독립 계정 인증으로 과장하지 않는다.
같은 source_event 재시도는 같은 ASG를 재사용하고 payload가 달라지면 충돌이다. 의미 있는 담당 변경·새 지시/범위 변경은 새 ASG로 선행 사건을 연결한다. 과거 ASG를 수정/삭제하지 않는다. 동시 분기는 관리자가 해소한다.

## 실제 절차
최신 main·등록·ROLE·COMMON_IO·W·현재 유효 업무채택 D·현재 R 내용·현재 ASG 체인을 확인한다. 업무 미채택/보류/반려 또는 요청 내용 변경으로 승인이 낡았으면 배정으로 우회하지 않는다. 승인되지 않은 새 업무를 이 절차에서 만들지 않는다.
관리자의 실제 의도에서 담당자·지시·승인된 brief를 정리하고 ASG-ID/이벤트 중복을 확인한다. 담당이 미정이면 그대로 둔다. W revision을 증가시키며 current_assignment_ref/assignment_refs와 담당·다음 행동을 연결한다. 다른 사람이나 다른 배정에 묶인 옛 계획 승인은 새로운 수행에 자동 적용하지 않는다.
채택과 배정/계획 결의가 같은 명확한 관리자 요청이면 하나의 논리적 변경 집합으로 만들되 역할·범위별 기록은 구분한다. 비승인 결정에서 배정·본 실행 권한을 만들지 않는다.
ASG/W/새 N/INBOX/작업지시 조회판/관련 업무 화면을 원자적으로 저장한다. 최신 parent와 expected blobs를 확인하고 force하지 않는다. 모두 실제 재조회한 후 배정 저장을 완료로 보고한다. 일부만 성공하면 같은 ASG/N ID로 복구하며 전체 성공이라고 하지 않는다.

## 최초 안내와 계속 보이는 할 일
새 담당자에게 N-<ASG-ID>-<actor_id> 사건을 만들며 본인이 이미 대표에게 구두 요청을 들었어도 정식 관리자 배정 안내를 생략하지 않는다. 기존 담당 해제/이전도 직접 영향 있는 수신자에게 안내한다. 관리자 자기 배정은 자기 알림을 기본 만들지 않는다.
다음 관련 회사 업무 대화에서 자기 INBOX의 새 배정을 한 번 안내하고, 실제 표시한 후에만 허용 범위에서 전달 기록을 남긴다. 읽기 전용/저장 금지에서는 대화 안 중복 방지만 하며 영속 기록 없는 새 대화의 정확히 한 번 전달을 보장하지 않는다.
records/assignment-views/<actor>.json은 현재 담당의 미완료 작업지시 목록이다. 알림 전달/확인과 무관하게 W가 완료/취소/재배정될 때까지 목적·지시·계획 상태·다음 행동을 계속 조회할 수 있다. 새 지시 팝업을 매번 재방송하는 것과 현재 해야 할 일을 보여주는 것을 구분한다.

## 구현 경계
scripts/work_plans.py는 배정/요약/실행 허가 검증을 보조하고 scripts/decision_flow.py가 변경 집합을 반환한다. 이 프로그램은 GitHub·채팅방을 스스로 쓰거나 감시하지 않는다. 별도 계정 인증/실시간 푸시/강제 ACL 구현은 별도다.
