# 업무검토·업무업데이트 — GOV-20260907-01

## 업무검토 — 세 역할, 읽기 전용
최신 FILE_MAP/ACTOR_REGISTRY/자기 ROLE/LLM_RUNTIME/COMPANY_OS/PRODUCT_REQUIREMENTS/PROJECT_REPOSITORIES/CURRENT_WORK 및 역할에 허용된 관련 기록·결정 인덱스만 읽는다. 부사수는 대표님의 전체 미배정 요청이 아니라 자기 기록/계획안/작업지시의 승인된 요약을 사용한다. 필요할 때만 관련 원문·정제본·실제 구현 저장소를 추가한다.
classification=idea/problem/work/mixed/policy_change, result=PASS/REVISION/HOLD, 현재 기준·중복/충돌·근거/미확인·제안 범위·권장 다음 행동과 이유를 출력한다. work는 업무 후보이지 승인된 일이라는 뜻이 아니다.
검토할 내용의 fingerprint/content_hash/revision, 기준 commit, 관련 결정·활성 제한·실제 접근 근거를 review_snapshot으로 표현한다. 이 명령만으로 R/검토파일/W/목차/알림 영수증을 쓰지 않고 나중 명시한 제출 때 저장한다.
아이디어는 아이디어저장, 문제는 문제저장, 실제 후보 PASS는 업무요청 또는 역할에 맞는 업무계획안제출을 안내한다. 대표님 구두 요청을 받은 부사수는 계획안까지 직접 제출할 수 있다. 실제 본 조사를 검토·기획 준비로 가장하지 않는다.

## 관련 과거 결정
같은 R/SUB는 최신 결정/과거 이유를 반드시 확인하고 새 후보는 같은 목적·대상·범위의 직접 중복만 찾아 읽는다. 단어 하나의 유사성이나 관련 없는 반려 이력으로 사람을 평가하지 않는다.
당시 결정·시점·이유 → 이번 변경·근거 → 사유 해소 여부 → 다음 행동을 구분한다. 과거 반려는 영구 금지가 아니다. 현재 유효한 held/지속 제한은 알림을 읽었더라도 수행 전 다시 확인하고 우회하지 않는다.

## 업무업데이트 — 관리자·현재 배정 부사수
W 없는 요청/계획안은 수행 업무의 갱신 대상이 아니다. 관리자 또는 현재 assigned_to인 부사수가 실제 수행자·시점·한 일·근거·결과 버전·문제·다음 행동을 기록한다. 보고자와 수행자를 나누며 없는 진행/성과/담당/마감을 만들지 않는다.
phase=planning은 승인된 업무의 계획 준비 기록일 뿐 본 작업 in_progress/전체 done으로 표시하지 않는다. phase=execution은 현재 업무채택 D + 현재 ASG/담당 + 정확한 계획 SUB/D/hash + 승인된 실제 활동 범위를 확인한다. 관리자 self_direct는 명시된 본인 범위만 가능하다. 미배정/오래된 담당/변경된 요청/보류·철회/무계획 실행은 차단한다.
신규 업무·배정 변경·승인 필드·범위 확대를 이 명령에 섞지 않는다. 새 범위는 새 검토/요청 또는 계획안 변경→관리자 결의다. 본문/계획 r2 제출만으로 이전 r1 승인을 새 범위에 재사용하지 않는다.
W revision을 올리고 CURRENT_WORK·ACTIVE/BLOCKED·관련 결정/작업지시 조회판·필요 HISTORY를 함께 처리한다. 순수 진행 갱신에 전체 제안 검토를 매번 강요하지 않지만 최신 승인 확인은 생략하지 않는다. 완료는 산출물·검증·필요 승인이 실제 충족된 경우만 한다.
첨부 원본은 materials/originals/<actor_id>/work/YYYY-MM-DD, 정제본은 normalized의 같은 맥락으로 source/W를 연결한다. 과거 D·회사 기준·미반영 I/P·타인 기록을 자동 변경하지 않는다. COMMON_IO로 검증 후 보고한다.
