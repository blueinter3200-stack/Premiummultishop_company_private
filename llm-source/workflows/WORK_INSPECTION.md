# 업무점검 — 대상별 관리자 조회 — GOV-20260906-03

명령: `/업무점검 <대상>`. ACT-001 관리자 전용, 읽기 전용이다.
예: `/업무점검 대표님`, `/업무점검 부사수`, `/업무점검 전체`, `/업무점검 ACT-003`.
구 `/대표업무점검`은 대상 ACT-002의 호환 별칭일 뿐이며 사용자에게는 새 이름을 안내한다.

## 대상

최신 ACTOR_REGISTRY에서 ID·표시명·현재 role을 해석한다. 전체는 등록된 허용 actor의 회사 업무 범위다. 역할명이 여러 사람에 해당하면 임의로 한 사람을 고르지 않고 이름/ID를 확인한다. 대상이 없고 대화에도 명확하지 않으면 대상만 묻고 전체 조회로 넓히지 않는다.

## 확인

PENDING_INDEX, REQUEST_INDEX, 대상 actor의 아이디어/문제 원문 목록과 상태, 관련 work/items·CURRENT_WORK·HISTORY, 관련 요청/directive·품의·결재·실행 기록을 확인한다. 개인 인사·개인화·타 저장소 비공개 직원 이력을 전수 조회하지 않는다.
ACT-002는 기존 records/ideas/representative 및 problems/representative도, ACT-001은 legacy admin 경로도 확인한다. ID가 없던 과거 기록은 기존 normalized catalog의 소유자 매핑으로 해석하고 이번 조회에서 원문을 바꾸지 않는다.
원문과 정제본·목차·첨부를 중복 건수로 세지 않는다. 전체 저장 건수는 실제 기록을 대조하고, 미반영 건수는 상태와 PENDING_INDEX를 대조한다. pending 목록만으로 전체 누적 저장 건수라고 하지 않는다. 누락·충돌은 보고만 한다.
진행 업무는 요청자/담당자/발안자 관계를 구분한다. 품의 작성 건수와 승인 건수, 요청 저장과 실행 완료를 따로 집계한다. 정보 기준기간·조회 커밋·확인 한계를 표시한다.

## 결과

대상/기간, 아이디어·문제 전체와 미반영, 최근 명확한 요청, 진행/차단 업무, 품의·결정대기, 기록/목차 불일치, 날짜·후속 확인, 회의 질문을 필요한 만큼 제시한다. 각 항목에 ID·원문 링크를 연결한다.
GitHub에 없는 대화·실제 행동을 알 수 없으므로 “저장 안 했다/일 안 했다/문제 없다”고 단정하지 않는다. 과거 계획 날짜 경과만으로 미수행을 판정하지 않는다.

## 금지

점검만으로 기록·REQUEST_INDEX·PENDING_INDEX·CURRENT_WORK·work/items·approvals·공식 소스를 수정하지 않는다. 요청 보존 규칙도 이 읽기 전용 경계를 넘지 않는다. 정리는 별도 명확한 관리자 변경 요청에서 수행한다.
