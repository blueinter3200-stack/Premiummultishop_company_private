# 업무점검 — GOV-20260907-01

ACT-001 전용 읽기 기능이다. `/업무점검 대표님`, `/업무점검 부사수`, `/업무점검 전체`, `/업무점검 ACT-003`처럼 대상과 필요 기간을 지정한다. 별칭은 없다.
현재 registry의 ID·표시명·role을 확인한다. 이름/직무가 여러 actor에 해당하면 임의로 고르지 않는다. 대상이 없고 문맥도 불명확하면 대상만 확인하고 전체로 확대하지 않는다.
PENDING_INDEX, REQUEST_INDEX, DECISION_INDEX·상태함, 대상 작성 아이디어/문제·요청·업무계획안, 관련 W·ASG·D·RC·실행 이력을 선택 확인한다. 자기 회사 업무 조회와 타인의 비공개 인사/개인화 자료 접근은 다르다.
기존 admin/representative 경로도 actor metadata로 연결하여 과거 기록을 놓치지 않는다. 원문·정제본·목차·첨부를 중복 건수로 세지 않는다. 전체 저장과 pending, 요청 제출과 업무 채택, 계획안 제출과 실행승인·실제 수행을 구분한다. 인덱스 누락은 원문을 대조하여 보고만 한다.
요청자·대리 기록자·배정자·담당자를 구분한다. ACT-002 구두 요청을 ACT-003이 기록한 건은 요청자별 집계와 기록자별 집계를 별도로 하며 두 업무로 세지 않는다. records/assignment-views에서 현재 배정, 계획 제출대기·결의대기·수정요청·수행·보류·종료를 보고 ASG 원문을 필요할 때만 읽는다.
현재 승인대기/수정요청/보류/승인/반려는 대상 최신 내용 버전·범위의 D에서 계산한다. 상태 폴더로 원문을 이동하지 않는다. 과거 결정은 관련 이력에서 확인하고 전체 반려를 매번 방송하지 않는다. 알림 전달/확인은 수행 완료가 아니고 전달 뒤 미완료 작업지시도 계속 남는다.
결과에는 대상/기간/조회 commit, 저장·미반영 건수, 요청·계획 상태, 진행·차단 업무, 결정 이유·후속 조건, 필요한 관리자 판단과 정확한 ID/경로를 포함한다. 실제 기록이 없음을 '일을 안 했다'로 단정하지 않는다.
이 명령만으로 R/W/ASG/D/인덱스/INBOX/전달 영수증/회사 기준을 쓰지 않는다. 별도 명확한 변경 요청에서만 허용 절차로 처리한다.
