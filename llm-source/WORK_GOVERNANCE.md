# Work Governance — GOV-20260907-01

## 객체와 권한
ACT=사람, R=원문 요청, I=아이디어, P=문제, SUB=업무계획안, D=관리자 결정, W=회사 업무, ASG=담당 작업지시, RC=관리자 요청의 의미 변경이다. 반복 방법은 플레이북이다. 최종 업무 채택·배정·계획 결의·공식 기준 변경은 ACT-001만 한다.
대표님은 방향과 업무요청, 부사수는 계획 수립·제출과 승인 범위 실무가 주 역할이다. 부사수도 새로운 일/현재 승인 범위 밖의 제안을 업무요청할 수 있다. 대표님 말만으로 부사수가 본 작업을 시작하지 않는다.

## 표준 및 구두 요청 진입
대화 → 필요 원문 보존 → 업무검토 → 업무요청 → 관리자 업무결정 → 담당 지정/작업지시 → 업무계획안제출 → 관리자 업무계획안결의 → 승인 범위 수행/업무업데이트다. 업무 채택과 계획 실행 허가는 같은 의미가 아니다.
대표님이 부사수에게 직접 구두로 요청한 경우는 원문 전달 사실을 보존하고 검토 후 업무계획안을 바로 제출할 수 있다. 업무요청·채택을 먼저 하라고 강제하지 않는다. 출처는 reported_oral_request이며 요청자와 실제 기록/제출자를 분리한다. 아직 본 작업 허가는 없다.
동일 요청을 상세화한다고 새 R/W를 중복 생성하지 않는다. 기존 기록이 확인 가능한 권한 범위에 있으면 연결하고, 접근할 수 없는 대표 원문을 임의 열람하지 않는다. 미정은 미정으로 남기고 duplicate/관련성 검토 결과를 관리자에게 보여준다.

## 검토·근거
최신 공식 기준·관련 업무·허용된 기록 인덱스·직접 관련된 원문·정제자료만 읽는다. 구현 사실이 중요할 때만 개발 저장소를 확인한다. 분류는 idea/problem/work/mixed/policy_change, 검토는 PASS/REVISION/HOLD와 다음 행동·이유다. PASS는 자동 제출·승인·착수가 아니다.
같은 R/SUB는 현재 결정과 과거 이유, 새 후보는 직접 동일/중복되는 건의 이유·이번 차이·해소 근거를 본다. 과거 반려를 작성자 평가나 영구 금지로 해석하지 않는다. 현재 유효한 보류/지속 제한은 우회하지 않는다. 읽기 전용 검토는 기록·원장·영수증까지 모두 비저장이다.
계획안에는 실제 내부 파일/범위/버전·외부 사례와 본 구간·목적·대안·방법·판단 이유·산출물·위험·미확인·필요 승인 범위를 포함한다. 계획 준비를 명분으로 본 조사·제작·지출을 먼저 실행하지 않는다.

## 배정과 상태
업무결정 승인과 담당 지정은 한 문장에 함께 있을 수 있지만 데이터는 따로 남긴다. ACT-003 지정 시만 ASG와 최초 알림을 만든다. 관리자 직접 수행에는 부사수 지시가 없고, 담당 미정은 배정대기다. 나중 배정/재배정도 같은 W에 새 ASG를 남긴다.
work/items는 상태 원장, CURRENT_WORK·assistant/30-working·assignment-views는 파생 조회판이다. 승인함/보류함 등은 대상 버전·범위의 D에서 계산하고 원문을 이동하지 않는다. 알림 전달은 업무 완료가 아니며 미완료 지시는 조회판에 남는다.
업무업데이트는 관리자 또는 현재 배정 부사수가 계획 준비와 실제 수행을 구분하여 쓴다. 실제 수행자와 기록자를 구분하고, 신규 업무·승인·범위 확대를 만들지 않는다. 완료는 실제 산출물·검증·필요 승인이 충족될 때만 한다. 문제 저장만으로 blocked/resolved가 되지 않는다.

## 결정·알림·보존
업무결정과 업무계획안결의는 명시한 승인/수정요청/보류/반려를 새 D로 기록한다. 비승인은 실제 이유와 빈 granted_scopes다. 승인 변경은 명시적 철회/재결재 없이 뒤집지 않는다. 다른 버전/범위의 결정으로 기존 승인을 자동 취소하지 않는다.
대표님의 관리자 제출 요청은 부사수에게 자동 배포하지 않는다. 부사수는 자기 기록과 받은 작업지시의 승인된 요약만 선택 조회한다. 최초 배정/재배정과 의미 있는 결정 변화는 관련 수신자에게 사건별로 안내한다. 반복 조회·옛 결정 소급 방송은 하지 않는다.
원문·과거 role 경로·ID·기존 R/W/D/RC·materials는 보존한다. 현재 관리자·대표 지시 충돌은 영향 범위를 구분하고 관리자가 조정한다. COMMON_IO대로 관련 기록/조회판을 원자적으로 저장·재조회하며 실제 계정 권한이나 푸시 구현을 문서만으로 주장하지 않는다.
