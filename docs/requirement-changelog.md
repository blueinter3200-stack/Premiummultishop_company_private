## 2026-09-06 — GOV-20260906-04

ACT-001의 첨부 작업 지시를 R-20260906-002 / W-20260906-004 / D-20260906-004에 연결한 호환 확장.

- 기존 R-ID/revision/supersedes를 유지하며 관리자 요구의 의미 변경 사건만 RC-YYYYMMDD-NNN으로 독립 보존한다.
- 변경 전/후 snapshot·이유 출처·관련 W/D·정확한 원문을 연결한다. 이유 미확인은 null/unknown이며 RC는 승인·완료·정책 확정이 아니다.
- REQUEST_CAPTURE 하위 절차, RC template/index, 관리자 로컬 지침과 검증·배포 도구를 추가한다. 기존 v1 요청은 강제 이관하지 않는다.
- 기존 15개 명령, 공통 로컬 트리거 안내, ACT-002/003 ROLE·지침과 권한은 변경하지 않는다. 공유 registry에는 RC 식별자/경로 메타데이터만 추가한다.
- 기존 요청·업무·결재·아이디어/문제·materials 원문을 수정하지 않는다. 검증 결과·설계 판단: docs/audits/GOV-20260906-04-implementation.md.

## 2026-09-06 — GOV-20260906-02

관리자 ACT-001의 현재 대화 지시에 따라 사람/기록 ID와 아이디어·문제·업무 라우팅 규칙을 공식 반영.

- GOV-025: 현재 세 actor를 `ACT-001` Jin, `ACT-002` 대표님, `ACT-003` 부사수로 등록. actor_id는 역할과 분리된 안정 ID이며 재사용하지 않음.
- GOV-026: 새 아이디어·문제는 actor_id 경로에 저장. 기존 role 기반 기록 6건은 참조 안정성을 위해 이동하지 않고 record_id/actor_id 메타데이터로 연결.
- 기존 아이디어 6건을 `I-YYYYMMDD-NNN` ID와 actor_id로 매핑하고 PENDING_INDEX/normalized catalog를 최신화.
- GOV-027: `/업무검토` PASS를 자동 `/업무공유`로 해석하지 않음. 검토 대상을 idea/problem/work/mixed/policy_change로 분류해 적합한 저장을 권장.
- 순수 아이디어를 업무공유하려 하면 라우팅 불일치로 막고 `/아이디어저장`을 안내. 순수 문제는 `/문제저장` 안내.
- GOV-028: 부사수도 ACT-003으로 아이디어·문제 저장 가능. 문제 저장은 자동 blocked, 아이디어 저장은 자동 업무 범위 변경을 의미하지 않음.
- GOV-029: 아이디어 자체와 그 아이디어를 조사·검증하는 업무를 별도 ID로 관리. 조사 완료는 아이디어 채택이 아님.
- 새 사람 합류 시 새 ACT-NNN 발급 → 현재 role/프로젝트 소스 연결 → 첫 아이디어·문제부터 actor_id 경로 사용. 직무 전용 작업공간은 필요할 때만 추가.
