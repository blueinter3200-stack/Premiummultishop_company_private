# Requirement Changelog

확정 요구사항의 추가·교체·삭제 또는 의미 있는 변경만 기록합니다. 단순 문구 수정은 기록하지 않습니다.

## 2026-08-20
- `/업무검토`가 공식 회사 기준과 CURRENT_WORK뿐 아니라 `records/PENDING_INDEX.md`를 통해 **현재 업무와 관련된 미반영 아이디어·문제까지 선별 확인**하도록 확장.
- 아이디어·문제 전체 원문을 매번 읽지 않고, PENDING_INDEX의 제목·요약·키워드·경로로 관련 기록만 선택적으로 읽는 규칙 확정.
- `/아이디어저장`·`/문제저장` 성공 시 PENDING_INDEX 추가, 관리자 반영 성공 시 제거하는 동기화 규칙 확정.
- 회사 관련 GitHub 저장소명을 `llm-source/PROJECT_REPOSITORIES.md`에서 관리하도록 확정.
- 실제 개발 진척·구현 상태가 필요한 질문은 레지스트리 설명으로 추론하지 않고 대상 저장소 최신 `main`을 직접 확인하도록 확정.

## 2026-08-19
- n8n을 회사 전체 OS의 연결·자동화 뼈대로 확정.
- ERP를 상품·SKU·재고·주문·판매·고객·구매·물류 운영 데이터의 핵심 원장으로 정의.
- ERP와 시장리서치·마케팅·CS·세무법률 간 필요한 데이터 양방향 교환 구조 확정.
- 대표님/관리자 모두 아이디어·문제 저장과 업무검토·업무공유 가능, 관리자만 공식 반영/업무확정 가능하도록 역할 분리.
- 진행·협의 중 업무는 `working/CURRENT_WORK.md` 전체 최신판으로 관리하고 확정 전에는 공식 요구사항과 분리하도록 확정.
- `/업무공유` 전에 `/업무검토`를 필수 게이트로 추가. 최신 공식 회사 방향·확정 요구사항·CURRENT_WORK와 비교해 `PASS / 공유 가능`인 경우에만 공유하도록 확정.
- 업무검토 PASS는 공식 확정이 아니라 진행업무판 공유 승인으로 정의하고, 공식 승격은 관리자 `/업무확정`으로만 수행하도록 분리.
- 기존 확정 기준의 변경안도 `업무검토 → 업무공유 → 관리자 업무확정` 순서를 거쳐 교체하도록 확정.
- 첨부자료는 가능한 경우 원본 보존 + LLM용 Markdown 정제본을 분리 저장하도록 확정. 아이디어·문제뿐 아니라 업무공유 첨부에도 동일 원칙 적용.
